# Understanding `compute_rewards()` in `3-PPO-fixed.py`

`compute_rewards()` converts a collected prompt-response batch into the fixed trajectory information needed by PPO:

- old-policy log probabilities;
- per-token rewards;
- old critic values;
- a response-token mask.

It does not update model weights. GAE and PPO updates happen later.

## 1. Function inputs

```python
def compute_rewards(
    input_data,
    query_tensors,
    response_tensors,
    score_tensors,
):
```

Suppose the batch size is $B$, the padded full-sequence length is $T$, and the vocabulary size is $V$.

- `input_data`: padded `query + response` sequences.

  ```python
  {
      "input_ids":      [B, T],
      "attention_mask": [B, T],
  }
  ```

- `query_tensors`: original variable-length prompt tensors.
- `response_tensors`: generated response tensors.
- `score_tensors`: one scalar reward-model score for each complete response.

The reward-model score has already been mapped into approximately $[-1,1]$.

## 2. Why use `torch.no_grad()`?

```python
with torch.no_grad():
```

This function describes the trajectory produced by the current policy before PPO updating begins.

PPO needs to remember:

$$
\pi_{\mathrm{old}}(A_t\mid S_t)
$$

and:

$$
V_{\mathrm{old}}(S_t).
$$

These quantities must remain fixed during the four subsequent PPO epochs. Therefore, this forward pass does not construct a gradient graph.

During `ppo_update()`, the script performs a new forward pass with gradients enabled to calculate:

$$
\pi_\theta(A_t\mid S_t).
$$

## 3. Current-policy and reference-policy outputs

```python
logits, all_values = model(**input_data)
ref_logits, _ = ref_model(**input_data)
```

The models receive the same complete sequences. Their output shapes are:

```text
logits:      [B, T, V]
all_values:  [B, T]
ref_logits:  [B, T, V]
```

Their meanings are:

- `logits`: token scores from the policy being optimized;
- `all_values`: critic estimates from the value head;
- `ref_logits`: token scores from the frozen SFT reference model.

The reference model prevents the PPO policy from moving too far from the original SFT policy.

### Understanding `all_values`

`all_values` contains the critic's estimate of the expected future return at every current state, before the next token is selected:

$$
V^\pi(S_t)
=
\mathbb{E}_{A_t,A_{t+1},\ldots\sim\pi}
\left[G_t\mid S_t\right].
$$

The expectation includes:

- which next token $A_t$ will be sampled;
- all later generated tokens;
- future KL penalties;
- the final reward-model score.

Suppose the currently generated tokens are:

```text
这 本 书
```

The current state is:

$$
S_t=\text{“这本书”}.
$$

At the position corresponding to `书`, the shared Transformer representation is sent to two heads:

```text
Transformer representation of “这本书”
                  │
          ┌───────┴────────┐
          │                │
       LM head         Value head
          │                │
 next-token logits     V(“这本书”)
```

The actor answers:

> Which next token should I choose?

For example:

```text
很: 0.40
真: 0.25
不: 0.15
```

The critic answers:

> Before choosing the next token, what total future reward do I expect if I continue using the current policy?

For example:

```text
V(“这本书”) = 0.72
```

The state value averages over all possible next tokens according to the policy:

$$
V^\pi(S_t)
=
\sum_a
\pi(a\mid S_t)Q^\pi(S_t,a).
$$

Therefore, `all_values` contains state-value estimates, not action-value estimates.

### What happens after choosing a token?

Suppose the actor chooses `很`. The new state becomes:

$$
S_{t+1}=\text{“这本书很”}.
$$

At the next position, the critic estimates:

$$
V^\pi(S_{t+1})
=
V^\pi(\text{“这本书很”}).
$$

The sequence is:

```text
Current state:       “这本书”
Critic estimate:     V(“这本书”)
Actor chooses:       “很”
Immediate reward:    R_t
New state:           “这本书很”
New critic estimate: V(“这本书很”)
```

These values are connected by the one-step TD error:

$$
\delta_t
=
R_t+\gamma V(S_{t+1})-V(S_t).
$$

### Difference between $V$ and $Q$

Choosing a particular next token and then estimating its expected return is an action-value function:

$$
Q^\pi(S_t,A_t)
=
\mathbb{E}\left[G_t\mid S_t,A_t\right].
$$

The script does not have a separate $Q$ head. Instead:

- `all_values[:, t]` estimates $V(S_t)$ before fixing the next action;
- after $A_t$ is chosen, `all_values[:, t + 1]` estimates $V(S_{t+1})$;
- a one-step estimate of the chosen action's value is:

$$
Q(S_t,A_t)
\approx
R_t+\gamma V(S_{t+1}).
$$

### Why is it called `all_values`?

```python
logits, all_values = model(**input_data)
```

It contains a value for every token position:

```text
all_values.shape = [batch_size, sequence_length]
```

| Token prefix | Value estimate |
|---|---|
| `这` | $V(S_0)$ |
| `这本` | $V(S_1)$ |
| `这本书` | $V(S_2)$ |
| `这本书很` | $V(S_3)$ |
| `这本书很好` | $V(S_4)$ |

Although the complete sequence is passed to the model at once, GPT-2's causal attention prevents position $t$ from seeing later tokens. Each value can therefore use only the current prefix.

These values are learned estimates, not true expected returns. The value head begins with essentially random values and learns through the PPO critic loss:

$$
L_{\mathrm{value}}
=
\left(
V_\phi(S_t)-\widehat V_t^{\mathrm{target}}
\right)^2.
$$

## 4. Causal shifting

Given:

```text
input_ids = [x0, x1, x2, ..., xT]
```

a causal model uses:

```text
logits at position 0 → predicts x1
logits at position 1 → predicts x2
logits at position 2 → predicts x3
...
```

Therefore:

```python
labels = input_data["input_ids"][:, 1:]
```

produces:

```text
labels = [x1, x2, ..., xT]
```

Meanwhile:

```python
logits[:, :-1, :]
```

removes the final logits because there is no next token in `input_data` to use as its label.

The aligned shapes are:

```text
logits[:, :-1, :]  [B, T-1, V]
labels              [B, T-1]
```

## 5. Extracting sampled-action log probabilities

First, `log_softmax` converts vocabulary logits into log probabilities:

```python
F.log_softmax(logits[:, :-1, :], dim=-1)
```

This produces:

$$
\log\pi_\theta(v\mid S_t)
$$

for every vocabulary token $v$.

PPO only needs the probability of the token that was actually generated. That token ID is stored in `labels`:

```python
logprobs = torch.gather(
    F.log_softmax(logits[:, :-1, :], dim=-1),
    2,
    labels.unsqueeze(-1),
).squeeze(-1)
```

The shape transformations are:

```text
all log probabilities: [B, T-1, V]
labels.unsqueeze(-1):  [B, T-1, 1]
after gather:           [B, T-1, 1]
after squeeze:          [B, T-1]
```

For each position, `gather()` selects:

$$
\log\pi_\theta(A_t\mid S_t),
$$

where $A_t$ is the token actually found in the generated sequence.

The same operation is performed for the frozen reference model:

```python
ref_logprobs = torch.gather(
    F.log_softmax(ref_logits[:, :-1, :], dim=-1),
    2,
    labels.unsqueeze(-1),
).squeeze(-1)
```

This gives:

$$
\log\pi_{\mathrm{ref}}(A_t\mid S_t).
$$

## 6. Per-token KL penalty

```python
beta = 0.2
rewards = -beta * (logprobs - ref_logprobs)
```

For one sampled token:

$$
\log\pi_\theta(A_t\mid S_t) - \log\pi_{\mathrm{ref}}(A_t\mid S_t)
=
\log
\frac{
\pi_\theta(A_t\mid S_t)
}{
\pi_{\mathrm{ref}}(A_t\mid S_t)
}.
$$

Because actions are sampled from $\pi_\theta$, the expectation of this sampled log-ratio is:

$$
D_{\mathrm{KL}}
\left(
\pi_\theta(\cdot\mid S_t)
\parallel
\pi_{\mathrm{ref}}(\cdot\mid S_t)
\right).
$$

The per-token PPO reward starts as:

$$
r_t^{\mathrm{KL}}
=
-\beta
\log
\frac{
\pi_\theta(A_t\mid S_t)
}{
\pi_{\mathrm{ref}}(A_t\mid S_t)
}.
$$

Here, $\beta=0.2$ controls the KL-penalty strength.

- If PPO makes a generated token much more likely than the reference model, it receives a negative penalty.
- If the two models remain close, the penalty is small.

An individual sampled KL term can be negative, but its expectation under the policy is non-negative.

## 7. Aligning masks and values

```python
masks = input_data["attention_mask"][:, 1:].clone().float()
values = all_values[:, :-1].clone()
```

The attention mask must be shifted like the labels:

```text
original mask: [corresponds to x0, x1, ..., xT]
shifted mask:  [corresponds to x1, x2, ..., xT]
```

The critic uses `all_values[:, :-1]` because each value must align with the next-token action predicted from that position:

$$
V(S_t)
\longleftrightarrow
A_t=x_{t+1}.
$$

## 8. Selecting only response actions

```python
for j in range(len(query_tensors)):
    start = len(query_tensors[j]) - 1
    end = start + len(response_tensors[j])
```

Suppose:

```text
query    = [q0, q1, q2]
response = [a0, a1]
```

The complete sequence is:

```text
[q0, q1, q2, a0, a1]
```

The causal prediction pairs are:

| Shifted position | State ends with | Predicted token | PPO response action? |
|---:|---|---|---|
| 0 | `q0` | `q1` | No |
| 1 | `q1` | `q2` | No |
| 2 | `q2` | `a0` | Yes |
| 3 | `a0` | `a1` | Yes |

The first response token `a0` is predicted by the logits at position 2. Because the query length is 3:

```text
start = 3 - 1
      = 2
```

The exclusive ending position is:

```text
end = start + response_length
    = 2 + 2
    = 4
```

Therefore, the valid response positions are `[start:end] = [2:4]`, meaning positions 2 and 3.

## 9. Removing prompt and padding positions

```python
masks[j, :start] = 0
masks[j, end:] = 0
```

The resulting mask is conceptually:

```text
prediction: q1  q2  a0  a1  PAD
mask:        0   0   1   1   0
```

Only generated response actions are used by PPO. Prompt-token predictions and padding positions are excluded.

## 10. Adding the reward-model score

```python
rewards[j, end - 1] += score_tensors[j]
```

The reward model produces one score for the complete response, not one score for each generated token. The script assigns that score to the final response action:

```text
response tokens:     a0       a1
KL rewards:         -KL_0    -KL_1
reward-model score:   0       score
```

Let the response contain $L$ token actions indexed by
$t=0,1,\ldots,L-1$. Every token before the final token receives only its KL
penalty:

$$
r_t=-\beta\,\mathrm{KL}_t,
\qquad 0\leq t<L-1.
$$

The final response token additionally receives the reward-model score:

$$
r_{L-1}
=
-\beta\,\mathrm{KL}_{L-1}+r_{\mathrm{RM}}.
$$

Here, the sampled per-token KL term is:

$$
\mathrm{KL}_t = \log
\frac{
\pi_\theta(A_t\mid S_t)
}{
\pi_{\mathrm{ref}}(A_t\mid S_t)
}.
$$

The complete response reward is consequently:

$$
R_{\mathrm{response}}
=
r_{\mathrm{RM}} -
\beta
\sum_t
\log
\frac{
\pi_\theta(A_t\mid S_t)
}{
\pi_{\mathrm{ref}}(A_t\mid S_t)
}.
$$

This combines:

- a terminal reward encouraging a high reward-model score;
- a dense token-level KL penalty discouraging excessive policy drift.

## 11. Applying the mask

```python
rewards = rewards * masks
values = values * masks
```

This sets prompt and padding positions to zero:

```text
rewards: [0, 0, response_reward_0, response_reward_1, 0]
values:  [0, 0, V(S_0),           V(S_1),           0]
masks:   [0, 0, 1,                1,                0]
```

`logprobs` is not multiplied by the mask here. However, the same mask is applied later inside the PPO loss, so excluded positions do not affect optimization.

## 12. Returned values

```python
return logprobs.detach(), rewards.detach(), values.detach(), masks
```

The outputs are:

| Output | Meaning | Shape |
|---|---|---|
| `logprobs` | Sampled-token log probabilities under the rollout/old policy | `[B, T-1]` |
| `rewards` | Per-token KL rewards plus the terminal reward-model score | `[B, T-1]` |
| `values` | Old critic estimates aligned with token actions | `[B, T-1]` |
| `masks` | Positions belonging to generated responses | `[B, T-1]` |

The next stage uses:

```python
advantages, returns = compute_advantage(rewards, values, masks)
```

Therefore, `compute_rewards()` does not calculate returns or GAE. It constructs the reward trajectory and fixed old-policy information from which GAE and the PPO loss are subsequently calculated.
