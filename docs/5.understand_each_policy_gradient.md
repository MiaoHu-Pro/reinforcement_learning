The scripts form a learning ladder:

```text
one policy-gradient update
        │
        ▼
full REINFORCE with reward-to-go
        │
        ├── vectorized implementation
        └── explicit step-by-step implementation
        │
        ▼
REINFORCE with a learned value baseline
        │
        ▼
n-step Actor–Critic
        │
        ▼
explicit one-step TD errors + GAE
```

## 1. The shared foundation

All six examples try to improve a policy:

$$
\pi_\theta(a|s)
=P(A_t=a\mid S_t=s)
$$

The policy is a neural network with parameters `theta`. For CartPole:

```text
Input state:
    cart position
    cart velocity
    pole angle
    pole angular velocity

Output:
    score/probability for pushing left
    score/probability for pushing right
```

During training, actions are sampled from the policy:

```python
distribution = Categorical(logits=policy(state))
action = distribution.sample()
```

Sampling is necessary for exploration. The policy must experience different
actions before it can learn which actions are useful.

## 2. The core policy-gradient idea

The policy should maximize expected return:

$$
J(\theta)
=\mathbb{E}_{\tau\sim\pi_\theta}[G_0]
$$

The policy-gradient learning signal contains:

$$
\nabla_\theta\log\pi_\theta(A_t|S_t)
$$

Conceptually:

```text
good learning signal
    → increase probability of the sampled action

bad learning signal
    → decrease probability of the sampled action
```

PyTorch minimizes losses, so all policy losses use a negative sign:

$$
L_{policy}
=-\text{learning signal}\times
\log\pi_\theta(A_t|S_t)
$$

What changes between the scripts is primarily the **learning signal**:

```text
code 1: artificial sampled_return = 1
code 2: Monte Carlo reward-to-go G_t
code 4: Monte Carlo reward-to-go G_t
code 5: Monte Carlo advantage G_t - V(S_t)
code 6: n-step advantage G_t^(n) - V(S_t)
code 7: one-step TD errors, combined with GAE for the actor
```

## 3. Important terms

| Term | Meaning |
|---|---|
| `S_t` | state before action at time `t` |
| `A_t` | action sampled at time `t` |
| `R_t` | reward observed after action `A_t` |
| `G_t` | discounted reward-to-go from time `t` |
| `V^pi(s)` | expected return from state `s` under policy `pi` |
| `V_phi(s)` | critic/value network approximation of `V^pi(s)` |
| `Q^pi(s,a)` | expected return after choosing `a` in `s` |
| advantage | how much better an action is than the state's average expectation |
| TD error | one-step value prediction error |
| bootstrap | use a value estimate for rewards not yet observed |

## 4. Trajectory, rollout, and transition

### Transition

One transition is:

$$
(S_t,A_t,R_t,S_{t+1})
$$

### Complete trajectory

One complete episode produces one trajectory:

$$
\tau
=(S_0,A_0,R_0,S_1,A_1,R_1,\ldots,S_T)
$$

### Short rollout

A rollout is a consecutive portion of a trajectory. `code-6` uses rollouts of
at most 20 transitions:

```text
one episode/trajectory
    ├── rollout 1: steps 0–19
    ├── rollout 2: steps 20–39
    └── rollout 3: remaining steps
```

This distinction matters because some algorithms update only after a complete
trajectory, while others update after short rollouts.

# Part I: the individual programs

## 5. Code 1: one policy-gradient update

File:
[`code-1-policy-gradient-single-update.py`](../rl_learning_demo/day02/code-1-policy-gradient-single-update.py)

### Purpose

This is not a full training algorithm. It demonstrates the smallest possible
policy-gradient operation:

1. reset CartPole;
2. sample one action;
3. assign an example return of `1.0`;
4. calculate one loss;
5. call `backward()`;
6. update once;
7. show that the sampled action's probability increased.

### Loss

The code uses:

```python
sampled_return = 1.0
loss = -sampled_return * torch.log(probabilities_before[action])
```

Mathematically:

$$
L=-1\times\log\pi_\theta(A_0|S_0)
$$

Because the return is positive, minimizing this loss increases the probability
of the sampled action.

### What this example teaches

- how a policy network produces action probabilities;
- how `Categorical` samples an action;
- why policy-gradient loss contains `log pi`;
- what `zero_grad()`, `backward()`, and `step()` do;
- how changing weights changes action probability.

### What it does not do

- it does not call `env.step()`;
- it does not collect a trajectory;
- it does not calculate real returns;
- it does not train a useful CartPole agent.

This file is a microscope for one gradient update, not a complete RL method.

## 6. Code 2: vectorized reward-to-go REINFORCE

File:
[`code-2-reinforce-policy-gradient-vectorized.py`](../rl_learning_demo/day02/code-2-reinforce-policy-gradient-vectorized.py)

### Algorithm

This is full Monte Carlo REINFORCE using reward-to-go:

$$
G_t
=R_t+\gamma R_{t+1}+\gamma^2R_{t+2}+\cdots
$$

The policy loss is:

$$
L_{policy}
=-\frac{1}{T}\sum_{t=0}^{T-1}
G_t\log\pi_\theta(A_t|S_t)
$$

### Workflow

```text
collect one complete episode
        │
        ▼
states, actions, rewards
        │
        ▼
calculate every G_t backward
        │
        ▼
evaluate all states in one neural-network batch
        │
        ▼
construct one loss
        │
        ▼
one backward() and one optimizer.step()
```

### Why it is called vectorized

All states are converted into one tensor:

```python
state_tensor.shape == [T, 4]
```

The policy evaluates them in one call:

```python
distribution = Categorical(logits=policy(state_tensor))
log_probabilities = distribution.log_prob(action_tensor)
```

The loss is calculated with tensor multiplication:

```python
loss = -(log_probabilities * returns).mean()
```

### Networks and updates

```text
Networks:             one policy network
Updates per episode:  one
Bootstrap:            no
Wait for episode end: yes
```

### Strengths

- mathematically direct;
- easy to connect to the REINFORCE equation;
- no learned value target;
- efficient batched PyTorch operations.

### Weaknesses

- Monte Carlo returns have high variance;
- every update depends on one complete sampled episode;
- it cannot learn until the episode ends;
- long episodes require storing the complete trajectory.

## 7. Code 4: step-by-step reward-to-go REINFORCE

File:
[`code-4-reinforce-policy-gradient-step-by-step.py`](../rl_learning_demo/day02/code-4-reinforce-policy-gradient-step-by-step.py)

### Algorithm

`code-4` implements the same reward-to-go REINFORCE algorithm as `code-2`:

$$
L_{policy}
=-\frac{1}{T}\sum_t
G_t\log\pi_\theta(A_t|S_t)
$$

It is not a new policy-gradient algorithm. The difference is implementation
style.

### Explicit backward loop

```python
return_from_t = 0.0

for reward, state, action in zip(
    reversed(rewards),
    reversed(states),
    reversed(actions),
):
    return_from_t = reward + gamma * return_from_t
    log_probability = policy_log_probability(state, action)
    loss_terms.append(-return_from_t * log_probability)
```

This loop shows exactly which action receives which return:

```text
A_(T-1) receives G_(T-1)
A_(T-2) receives G_(T-2)
...
A_0     receives G_0
```

### Code 2 versus Code 4

| Question | Code 2 | Code 4 |
|---|---|---|
| Algorithm | reward-to-go REINFORCE | reward-to-go REINFORCE |
| Mathematical loss | same | same |
| Return calculation | separate vector | inside reverse loop |
| Policy forward pass | one batched call | one call per state |
| Efficiency | higher | lower |
| Educational visibility | compact | very explicit |

Use `code-4` to understand the mechanics. Use the vectorized form in `code-2`
when efficiency and concise tensor code matter.

## 8. Code 5: REINFORCE with a learned value baseline

File:
[`code-5-reinforce-policy-gradient-value-baseline.py`](../rl_learning_demo/day02/code-5-reinforce-policy-gradient-value-baseline.py)

### New idea

Raw return does not say whether the result was better than normally expected
from that state. Code 5 adds a neural-network state-value baseline:

$$
V_\phi(s)\approx V^\pi(s)
$$

It constructs a Monte Carlo advantage:

$$
Adv_t
=G_t-V_\phi(S_t)
$$

### Actor/policy loss

$$
L_{policy}
=-\frac{1}{T}\sum_t
\log\pi_\theta(A_t|S_t)
\operatorname{stopgrad}(Adv_t)
$$

### Value-network loss

The complete sampled return is the regression target:

$$
L_{value}
=\frac{1}{T}\sum_t
\left(V_\phi(S_t)-G_t\right)^2
$$

### Why subtract a baseline?

```text
G_t = 20, V(S_t) = 5
    advantage = +15
    much better than expected

G_t = 20, V(S_t) = 19
    advantage = +1
    only slightly better than expected

G_t = 20, V(S_t) = 25
    advantage = -5
    worse than expected
```

The baseline reduces gradient variance by comparing the action outcome against
a state-dependent expectation.

### Does the baseline bias the policy gradient?

An action-independent baseline does not bias the expected policy gradient when
it is treated as fixed in the policy loss:

$$
\mathbb{E}_{A\sim\pi}
\left[
\nabla_\theta\log\pi_\theta(A|S)b(S)
\right]=0
$$

The value estimate can be inaccurate, but `detach()` prevents the policy loss
from changing the value network:

```python
advantages.detach()
```

### Networks and updates

```text
Networks:             policy + value
Updates per episode:  one policy update + one value update
Bootstrap:            no
Value target:         complete Monte Carlo G_t
Wait for episode end: yes
```

### Is this Actor–Critic?

It has actor-like and critic-like networks, but the most precise name is
**Monte Carlo REINFORCE with a learned value baseline** because it waits for the
complete episode and does not bootstrap.

## 9. Code 6: n-step Actor–Critic

File:
[`code-6-actor-critic.py`](../rl_learning_demo/day02/code-6-actor-critic.py)

### New idea: bootstrap before the episode ends

Code 6 collects a short rollout and estimates the unknown future using the
critic:

$$
G_t^{(n)}
=R_t+\gamma R_{t+1}+\cdots
+\gamma^{n-1}R_{t+n-1}
+\gamma^nV_\phi(S_{t+n})
$$

The advantage is:

$$
Adv_t^{(n)}
=G_t^{(n)}-V_\phi(S_t)
$$

### Update timing

With the default `rollout_steps=20`:

```text
collect up to 20 transitions
        │
        ▼
bootstrap from critic V(S_end)
        │
        ▼
calculate n-step returns
        │
        ▼
update actor and critic
        │
        ▼
continue the same episode with new weights
```

One episode can therefore contain several updates.

### Actor loss

$$
L_{actor}
=-\frac{1}{m}\sum_t
\log\pi_\theta(A_t|S_t)
\operatorname{stopgrad}(Adv_t^{(n)})
-\beta\mathcal{H}(\pi_\theta)
$$

The entropy term encourages continued exploration.

### Critic loss

The critic predicts n-step bootstrapped returns. The implementation uses Huber
loss rather than MSE for improved robustness to changing targets.

### Stability tools

- short rollouts;
- entropy bonus;
- Huber critic loss;
- detached actor advantages;
- gradient clipping;
- correct terminal/truncation bootstrapping.

### Networks and updates

```text
Networks:             actor + critic
Updates per episode:  potentially several
Bootstrap:            yes, after each rollout
Value target:         n-step return
Wait for episode end: no
```

### Bias–variance position

An n-step target lies between Monte Carlo and one-step TD:

```text
more observed rewards than one-step TD
    → less bootstrap bias

fewer observed rewards than full Monte Carlo
    → lower sampling variance and earlier updates
```

## 10. Code 7: explicit one-step TD errors and GAE

File:
[`code-7-actor-critic-one-step-td-error.py`](../rl_learning_demo/day02/code-7-actor-critic-one-step-td-error.py)

### Exact one-step TD target

For every stored transition:

$$
y_t^{TD}
=R_t+\gamma V_\phi(S_{t+1})
$$

At true termination, the future value is zero:

$$
y_t^{TD}=R_t
$$

### Exact one-step TD error

$$
\delta_t
=R_t+\gamma V_\phi(S_{t+1})-V_\phi(S_t)
$$

This TD error has two roles:

```text
critic:
    value-prediction error

actor:
    one-step sample estimate of advantage
```

### Why TD error approximates advantage

The true advantage is:

$$
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s)
$$

The one-step sample approximates `Q` with:

$$
R_t+\gamma V_\phi(S_{t+1})
$$

Therefore:

$$
\delta_t\approx A^\pi(S_t,A_t)
$$

### GAE for the actor

The critic always learns from the exact one-step TD target. For more stable
actor credit assignment, the default actor combines TD errors:

$$
A_t^{GAE}
=\delta_t
+\gamma\lambda\delta_{t+1}
+(\gamma\lambda)^2\delta_{t+2}
+\cdots
$$

The default is:

```text
lambda = 0.95
```

With:

```bash
--gae-lambda 0
```

the actor uses only the direct one-step error:

$$
A_t^{GAE}=\delta_t
$$

### Important implementation choice

Code 7 collects one complete episode, then computes all one-step TD errors as a
batch. Therefore:

```text
TD target:            one-step
Data collection:      complete episode
Updates per episode:  one actor + one critic
```

Using a one-step target does not automatically mean the implementation must
update after every single environment step.

### Additional stability choices

- standardize GAE advantages for the actor;
- entropy bonus to preserve exploration;
- Huber critic loss;
- gradient clipping;
- bound CartPole value estimates to the valid discounted range `[0, 50]`;
- bootstrap on time-limit truncation, but not on true termination.

## 14. Return-target comparison

### Monte Carlo target

Used by Codes 2, 4, and 5:

$$
G_t
=R_t+\gamma R_{t+1}+\cdots
$$

Only real observed rewards are used. No critic prediction appears in the
return target.

### n-step target

Used by Code 6:

$$
G_t^{(n)}
=R_t+\cdots+\gamma^nV(S_{t+n})
$$

Some rewards are observed; the remaining future is bootstrapped.

### one-step target

Used by Code 7's critic:

$$
y_t^{TD}=R_t+\gamma V(S_{t+1})
$$

Only one reward is observed before bootstrapping.

## 15. Bias–variance continuum

```text
Lower bootstrap bias                                Lower sampling variance
Higher sampling variance                            Higher bootstrap bias

full Monte Carlo ───── long n-step ───── short n-step ───── one-step TD
Codes 2/4/5               Code 6                       Code 7 critic
```

### Monte Carlo

- uses real rewards through episode end;
- does not depend on critic predictions for the return;
- has high variance across sampled trajectories;
- updates later.

### Bootstrapped TD

- uses the critic to estimate an unknown future;
- can update from less data;
- often has lower variance;
- inherits bias when the critic is inaccurate;
- can become unstable if actor and critic learning are poorly balanced.

## 16. Why `detach()` appears

In Codes 5, 6, and 7, the actor's learning signal contains critic values. The
actor should treat that signal as a fixed assessment:

```python
advantages.detach()
```

This separates responsibilities:

```text
actor loss
    → train policy/actor only

critic loss
    → train value/critic only
```

Without `detach()`, the actor loss could change the critic simply to make the
actor objective numerically smaller.

## 17. Why actor and critic losses do not steadily decrease

Supervised-learning intuition can be misleading here. The data distribution
changes whenever the policy changes.

```text
actor improves
    → visits new states
    → critic receives new targets
    → critic loss may rise
    → advantages and actor loss change scale
```

The primary performance metric is episode return and its moving average, not a
monotonically decreasing actor loss.

## 18. Termination versus truncation

For bootstrapped Codes 6 and 7:

```text
terminated=True
    true task terminal
    future task value = 0

truncated=True
    external time limit
    future task value is not necessarily 0
    retain critic bootstrap
```

Monte Carlo Codes 2, 4, and 5 stop collection for either condition. The
bootstrapped scripts must additionally decide whether future value should be
zero, which depends only on true termination.

## 19. Policy Gradient, REINFORCE, and Actor–Critic terminology

### Policy Gradient

The broad family of algorithms that directly optimize policy parameters.

### REINFORCE

A Monte Carlo policy-gradient method that weights action log-probabilities by
sampled returns or return-based advantages.

```text
Codes 2 and 4: REINFORCE
Code 5:        REINFORCE with learned baseline
```

### Actor–Critic

A policy-gradient method where a critic learns a value function and provides
bootstrapped learning signals to an actor.

```text
Code 6: n-step Actor–Critic
Code 7: one-step TD critic with GAE actor
```

Code 5 has actor- and critic-like networks but remains Monte Carlo because its
value target is the complete observed `G_t`.

# Part III: practical mental models

## 20. A single action viewed by each algorithm

Suppose the agent takes action `A_t` in state `S_t`.

### Code 1

```text
Assume return = 1
Increase probability of A_t
```

### Codes 2 and 4

```text
Wait for episode end
Calculate all rewards after A_t
Weight A_t by G_t
```

### Code 5

```text
Wait for episode end
Calculate G_t
Ask whether G_t was better than V(S_t)
Weight A_t by G_t - V(S_t)
```

### Code 6

```text
Observe several future rewards
Estimate the remaining future using V(S_(t+n))
Weight A_t by n-step return - V(S_t)
```

### Code 7

```text
Observe R_t and S_(t+1)
Calculate delta_t = R_t + gamma*V(S_(t+1)) - V(S_t)
Use delta_t directly or combine future deltas with GAE
```

## 22. Common misunderstandings

### “Code 2 and Code 4 are different algorithms.”

No. They implement the same reward-to-go REINFORCE loss. One is vectorized; the
other exposes the backward loop.

### “A value baseline always makes the policy gradient biased.”

No. An action-independent baseline does not bias the expected policy gradient
when detached correctly. Bootstrapped targets introduce a separate
bias–variance trade-off.

### “Having a value network automatically means Actor–Critic.”

Not necessarily. Code 5 has a value network but uses complete Monte Carlo
returns. Codes 6 and 7 use critic bootstrapping.

### “One-step TD means the weights must update after every step.”

No. The target can be one-step while transitions are updated as a batch. Code 7
calculates one-step targets but batches one episode.

### “`backward()` updates the weights.”

No:

```text
backward()
    calculates and stores gradients

optimizer.step()
    changes the weights
```

### “A lower actor loss always means a better policy.”

No. Policy loss depends on sampled actions, changing advantages, entropy, and a
changing state distribution. Use episode return to assess performance.

## 24. Final summary

The six programs progressively replace a simple return signal with increasingly
informed and timely estimates:

```text
Code 1
    prove one policy-gradient update works

Code 2
    train with vectorized Monte Carlo reward-to-go

Code 4
    expose the same REINFORCE calculation step by step

Code 5
    subtract learned state value to reduce policy-gradient variance

Code 6
    bootstrap from a critic after short n-step rollouts

Code 7
    expose the exact one-step TD error and build GAE from TD errors
```

The conceptual progression is:

$$
\text{return}
\longrightarrow
\text{return minus baseline}
\longrightarrow
\text{bootstrapped advantage}
\longrightarrow
\text{TD-error-based advantage}
$$

All are policy-gradient methods because the actor/policy is ultimately trained
through gradients of:

$$
\log\pi_\theta(A_t|S_t)
$$

Their main differences are how they estimate action quality, when they update,
whether they learn a value function, and how they balance bias against
variance.
