# Using `transformers chat` with Qwen3

The `transformers chat` command is an interactive chat **client**. It does not
load a model by itself. A `transformers serve` process must first load the
model and expose an OpenAI-compatible API, normally at
`http://localhost:8000`.

The workflow therefore uses two terminals:

```text
Terminal 1: transformers serve -> loads Qwen3 and starts the API server
Terminal 2: transformers chat  -> sends your messages to that API server
```

## 1. Install the serving dependencies

Run this once from the project root:

```bash
cd /local/scratch/mh1f25/python_projects/reinforcement_learning
uv add "transformers[serving]"
```

The serving extra provides packages such as FastAPI and Uvicorn. The `uv add`
command records the dependency in `pyproject.toml` and installs it in `.venv`.

You can verify the commands with:

```bash
uv run transformers serve --help
uv run transformers chat --help
```

## 2. Start the model server in terminal 1

The local base model is stored at:

```text
/home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base
```

Start it on the GPU:

```bash
cd /local/scratch/mh1f25/python_projects/reinforcement_learning

uv run transformers serve \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    --device cuda \
    --dtype bfloat16 \
    --reasoning auto
```

Keep this terminal running. By default, the API listens at:

```text
http://localhost:8000
```

The important arguments are:

- `FORCE_MODEL`: the model directory immediately following `serve`.
- `--device cuda`: run inference on the GPU.
- `--dtype bfloat16`: reduce GPU memory usage compared with `float32`.
- `--reasoning auto`: let the Qwen3 chat template decide whether to use its
  thinking/reasoning mode.

If the GPU does not support `bfloat16`, use:

```bash
--dtype float16
```

To run without Qwen3 thinking output, use:

```bash
--reasoning off
```

To run on the CPU for testing, use:

```bash
uv run transformers serve \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    --device cpu \
    --dtype float32 \
    --reasoning off
    --port 5003
```

CPU generation will be considerably slower than GPU generation.

## 3. Open the interactive chat in terminal 2

Open another terminal, enter the project, and connect to the server:

```bash
cd /local/scratch/mh1f25/python_projects/reinforcement_learning

uv run transformers chat \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    http://localhost:5003 \
    max_new_tokens=512 temperature=0.7 do_sample=True
```

You can now type a message and press Enter. The generation arguments mean:

- `max_new_tokens=512`: generate no more than 512 new tokens per response.
- `temperature=0.7`: control sampling randomness; smaller values are more
  predictable.
- `do_sample=True`: sample tokens instead of always taking the most likely
  token.

For more deterministic output, use:

```bash
uv run transformers chat \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    http://localhost:5003 \
    max_new_tokens=512 do_sample=False
```

Use `Ctrl+C` to exit the chat. Use `Ctrl+C` in terminal 1 when you also want to
stop the model server.

## 4. Add a system prompt

The chat client can send a system instruction:

```bash
uv run transformers chat \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    http://localhost:5003 \
    --system-prompt "You are a helpful reinforcement-learning tutor." \
    max_new_tokens=512 temperature=0.7 do_sample=True
```

Options such as `--system-prompt` must appear before generation settings such
as `max_new_tokens=512`.

## 5. Chat with an SFT or DPO checkpoint

After training, replace the base-model path in **both** terminal commands with
the output checkpoint. For example, the modern SFT script saves to:

```text
outputs/Qwen3-0.6B-Base-UltraChat-SFT
```

Start that model with:

```bash
uv run transformers serve \
    outputs/Qwen3-0.6B-Base-UltraChat-SFT \
    --device cuda \
    --dtype bfloat16 \
    --reasoning auto
```

Then connect using the same model identifier:

```bash
uv run transformers chat \
    outputs/Qwen3-0.6B-Base-UltraChat-SFT \
    http://localhost:5003 \
    max_new_tokens=512 temperature=0.7 do_sample=True
```

## 6. Common problems

### `ModuleNotFoundError: No module named 'fastapi'`

Install the Transformers serving dependencies:

```bash
uv add "transformers[serving]"
```

### Connection refused at `localhost:5003`

The server is not running, is still loading the model, or is using a different
port. Start terminal 1 first and wait until the server is ready.

If port 5003 is already occupied, start the server on another port:

```bash
uv run transformers serve \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    --device cuda \
    --port 5004
```

Then connect the client to the same port:

```bash
uv run transformers chat \
    /home/mh1f25/scratch/llms_model/Qwen3-0.6B-Base \
    http://localhost:5004
```

### CUDA out-of-memory error

Stop other GPU processes if appropriate, use `float16` or `bfloat16`, shorten
`max_new_tokens`, or test with `--device cpu`.

### Why `transformers chat Qwen3-0.6B-Base` is insufficient

That command only starts the client and tries to connect to the default server
at `http://localhost:5003`. It neither starts the server nor resolves your
local model directory from an unrelated working directory. Starting
`transformers serve` first and using the full path avoids both problems.
