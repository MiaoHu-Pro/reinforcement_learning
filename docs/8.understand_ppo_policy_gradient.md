# Why PPO does not directly show `-TD error * log policy`

This note answers a question about
[`code-3-old.py`](../rl_learning_demo/day03/code-3-old.py):

> Why does the PPO code not contain a loss written directly as
> $-\delta_t\log\pi_\theta(A_t\mid S_t)$?

The modern implementation is
[`code-3-ppo-clipped-objective-GAE.py`](../rl_learning_demo/day03/code-3-ppo-clipped-objective-GAE.py).

## 1. The short answer

The observation is correct. PPO does not directly optimize:

$$
-\delta_t\log\pi_\theta(A_t\mid S_t).
$$

It makes two changes:

1. It replaces the single one-step TD error $\delta_t$ with the multi-step GAE
   advantage $\widehat A_t^{\mathrm{GAE}}$.
2. It replaces direct multiplication by the log probability with a clipped
   probability-ratio objective.

The progression is:

```text
one-step Actor-Critic
    -delta_t * log pi_theta(A_t | S_t)

Actor-Critic with GAE
    -A_GAE_t * log pi_theta(A_t | S_t)

PPO-Clip with GAE
    -min(
        ratio_t * A_GAE_t,
        clipped_ratio_t * A_GAE_t
    )
```

Although PPO does not display $\nabla_\theta\log\pi_\theta$ directly, that
gradient is still present. PyTorch obtains it by differentiating the PPO ratio.

## 2. The familiar one-step Actor–Critic loss

The one-step TD target is:

$$
y_t^{(1)}
=
R_t +
\gamma(1-d_t)V_\omega(S_{t+1}).
$$

The one-step TD error is:

$$
\boxed{
\delta_t
=
R_t +
\gamma(1-d_t)V_\omega(S_{t+1}) -
V_\omega(S_t)
}
$$

A basic one-step Actor–Critic loss is:

$$
\boxed{
L_{\mathrm{actor}}(\theta)
=
-\delta_t
\log\pi_\theta(A_t\mid S_t)
}
$$

Its gradient is:

$$
\nabla_\theta L_{\mathrm{actor}}(\theta)
=
-\delta_t
\nabla_\theta\log\pi_\theta(A_t\mid S_t),
$$

where $\delta_t$ is treated as a detached constant for the actor update.

This loss uses each transition once. It does not contain an old policy or a
probability ratio.

## 3. The TD error is present in `code-3-old.py`

The legacy PPO code first calculates the one-step target:

```python
td_target = rewards + self.gamma * self.v(next_states) * (1 - dones)
```

This represents:

$$
y_t^{(1)}
=
R_t+\gamma(1-d_t)V_\omega(S_{t+1}).
$$

It then subtracts the current-state value:

```python
td_delta = td_target - v
```

Therefore, `td_delta` contains:

$$
[\delta_0,\delta_1,\ldots,\delta_{T-1}].
$$

The TD error has not disappeared. PPO uses it as the building block for GAE.

## 4. PPO uses GAE instead of only the current TD error

The code calls:

```python
gae = self.compute_gae(td_delta.cpu())
```

The backward recursion is:

$$
\boxed{
\widehat A_t^{\mathrm{GAE}}
=
\delta_t +
\gamma\lambda\widehat A_{t+1}^{\mathrm{GAE}}
}
$$

Expanding it gives:

$$
\widehat A_t^{\mathrm{GAE}}
=
\delta_t +
(\gamma\lambda)\delta_{t+1} +
(\gamma\lambda)^2\delta_{t+2} +
\cdots.
$$

The basic one-step loss uses only $\delta_t$. PPO in this file uses the entire
weighted sequence $\widehat A_t^{\mathrm{GAE}}$.

This is the first reason the exact expression

$$
-\left(
R_t+\gamma V(S_{t+1})-V(S_t)
\right)
\log\pi_\theta(A_t\mid S_t)
$$

does not appear.

## 5. Why PPO introduces an old policy

The trajectory is generated before the update by a fixed policy called the
**old policy**:

$$
\pi_{\mathrm{old}}.
$$

The code saves the probability of every sampled action and then freezes its
logarithm:

```python
old_log_probs = torch.log(old_probs).detach()
```

During PPO optimization, the same trajectory is reused ten times. After every
optimizer step, the current policy $\pi_\theta$ changes, but
$\pi_{\mathrm{old}}$ must remain fixed.

Without an old-policy reference or another constraint, repeatedly optimizing
the same data could move the policy too far from the policy that generated
that data.

## 6. `log_probs` is still the current log policy

The code calculates:

```python
log_probs = torch.log(self.pi(states).gather(1, actions))
```

This is exactly:

$$
\boxed{
\texttt{log\_probs}
=
\log\pi_\theta(A_t\mid S_t)
}
$$

`gather()` selects the probability of the action actually taken. For example:

```text
policy probabilities:
    S_0 -> [0.30, 0.70]
    S_1 -> [0.80, 0.20]

collected actions:
    [1, 0]

gather result:
    [0.70, 0.80]

log result:
    [log pi_theta(A_0=1 | S_0),
     log pi_theta(A_1=0 | S_1)]
```

Therefore, the log-policy expression is present in the program. It is not
directly multiplied by the advantage because PPO next uses it to construct a
probability ratio.

## 7. The PPO probability ratio

The code calculates:

```python
ratio = torch.exp(log_probs - old_log_probs)
```

Using

$$
\exp(\log x-\log y)=\frac{x}{y},
$$

this becomes:

$$
\boxed{
r_t(\theta)
=
\frac{
\pi_\theta(A_t\mid S_t)
}{
\pi_{\mathrm{old}}(A_t\mid S_t)
}
=
\exp\left(
\log\pi_\theta(A_t\mid S_t) -
\log\pi_{\mathrm{old}}(A_t\mid S_t)
\right)
}
$$

The ratio does not replace the log policy. It is constructed from the current
and old log policies.

Its interpretation is:

- $r_t(\theta)=1$: the sampled action's probability is unchanged.
- $r_t(\theta)>1$: the new policy makes the action more likely.
- $r_t(\theta)<1$: the new policy makes the action less likely.

## 8. Why the log-policy gradient is inside the ratio

The old log probability is detached, so it is constant with respect to
$\theta$:

$$
\nabla_\theta
\log\pi_{\mathrm{old}}(A_t\mid S_t)=0.
$$

Differentiate the ratio:

$$
\nabla_\theta r_t(\theta)
=
\nabla_\theta
\exp\left(
\log\pi_\theta -
\log\pi_{\mathrm{old}}
\right).
$$

Using the chain rule:

$$
\boxed{
\nabla_\theta r_t(\theta)
=
r_t(\theta)
\nabla_\theta
\log\pi_\theta(A_t\mid S_t)
}
$$

This equation is the key connection. PPO's ratio carries the familiar
log-policy gradient.

## 9. The unclipped PPO objective

Before clipping, PPO uses:

```python
surr1 = ratio * gae
```

For one transition:

$$
J_t^{\mathrm{unclipped}}(\theta)
=
r_t(\theta)\widehat A_t^{\mathrm{GAE}}.
$$

Because PyTorch minimizes a loss, define:

$$
L_t^{\mathrm{unclipped}}(\theta)
=
-r_t(\theta)\widehat A_t^{\mathrm{GAE}}.
$$

Treating GAE as a detached constant gives:

$$
\begin{aligned}
\nabla_\theta L_t^{\mathrm{unclipped}}
&=
-\widehat A_t^{\mathrm{GAE}}
\nabla_\theta r_t(\theta) \\
&=
-r_t(\theta)
\widehat A_t^{\mathrm{GAE}}
\nabla_\theta\log\pi_\theta(A_t\mid S_t).
\end{aligned}
$$

Thus:

$$
\boxed{
\nabla_\theta L_t^{\mathrm{unclipped}}
=
-r_t(\theta)
\widehat A_t^{\mathrm{GAE}}
\nabla_\theta\log\pi_\theta(A_t\mid S_t)
}
$$

The policy-gradient term is still present even though the loss does not show
`gae * log_probs` directly.

## 10. Why the first PPO gradient resembles the direct loss

At the beginning of the first PPO epoch, the current policy and old policy are
the same:

$$
\pi_\theta=\pi_{\mathrm{old}}.
$$

Therefore:

$$
r_t(\theta)\approx1.
$$

The unclipped PPO gradient becomes:

$$
\nabla_\theta L_t^{\mathrm{unclipped}}
\approx
-\widehat A_t^{\mathrm{GAE}}
\nabla_\theta\log\pi_\theta(A_t\mid S_t).
$$

This is the same gradient form produced by the direct GAE Actor–Critic loss:

$$
L_t^{\mathrm{GAE-AC}}
=
-\widehat A_t^{\mathrm{GAE}}
\log\pi_\theta(A_t\mid S_t).
$$

The numerical loss values are not the same, but their initial policy-gradient
directions agree when the ratio is one and clipping is inactive.

An important detail is that $r_t=1$ does not mean its gradient is zero:

$$
r_t=1
\quad\not\Rightarrow\quad
\nabla_\theta r_t=0.
$$

Instead:

$$
\nabla_\theta r_t
=
\nabla_\theta\log\pi_\theta(A_t\mid S_t)
$$

when the ratio value is one.

## 11. The clipped PPO objective

The second surrogate is:

```python
surr2 = torch.clamp(ratio, 0.8, 1.2) * gae
```

With clipping distance $\epsilon=0.2$:

$$
\operatorname{clip}
\left(r_t(\theta),1-\epsilon,1+\epsilon\right)
=
\operatorname{clip}(r_t(\theta),0.8,1.2).
$$

The final actor loss is:

```python
loss_pi = torch.mean(-torch.min(surr1, surr2))
```

Mathematically:

$$
\boxed{
L_{\mathrm{PPO}}(\theta)
=
-\frac1N
\sum_t
\min\left(
r_t(\theta)\widehat A_t^{\mathrm{GAE}},
\operatorname{clip}
\left(r_t(\theta),0.8,1.2\right)
\widehat A_t^{\mathrm{GAE}}
\right)
}
$$

The minimum creates a conservative objective.

### Positive advantage

When $\widehat A_t>0$, the action was better than expected, so the actor tries
to increase its probability. Once $r_t>1.2$, the clipped branch prevents
additional objective improvement from increasing that probability farther.

### Negative advantage

When $\widehat A_t<0$, the action was worse than expected, so the actor tries
to decrease its probability. Once $r_t<0.8$, clipping prevents additional
objective improvement from decreasing it farther.

Clipping is why PPO can perform multiple optimization epochs on the same
trajectory more safely than an unconstrained policy-gradient update.

## 12. Where `backward()` finds the gradient

The relevant computation graph is:

```text
loss_pi
    |
    v
minimum(surr1, surr2)
    |
    v
probability ratio * detached GAE
    |
    v
exp(new_log_probability - detached_old_log_probability)
    |
    v
log pi_theta(A_t | S_t)
    |
    v
actor parameters theta
```

When the code calls:

```python
loss_pi.backward()
```

PyTorch applies the chain rule through this graph. It calculates

$$
\nabla_\theta L_{\mathrm{PPO}}(\theta),
$$

which includes

$$
\nabla_\theta\log\pi_\theta(A_t\mid S_t)
$$

for samples whose selected PPO branch has a nonzero gradient.

The gradient expression is therefore generated by autograd rather than written
manually in the source code.

## 13. What is detached and why?

Three quantities must remain fixed during the repeated policy updates:

### Old log probabilities

```python
old_log_probs = torch.log(old_probs).detach()
```

They describe the policy that generated the trajectory. If they changed with
the new actor, the ratio would no longer compare new and old policies.

### GAE advantages

`compute_gae()` calls `detach()` and converts the TD errors to NumPy. Therefore,
GAE is a fixed actor learning signal. The actor loss must not train the critic.

### Old values in critic targets

```python
v = self.v(states).detach()
```

The critic target is:

$$
\widehat V_t^{\mathrm{target}}
=
\widehat A_t^{\mathrm{GAE}}
+
V_{\mathrm{old}}(S_t).
$$

This target stays fixed while the new critic is trained toward it.

## 14. Direct mapping from mathematics to code

| Mathematical quantity | `code-3-old.py` |
|---|---|
| $y_t^{(1)}$ | `td_target` |
| $\delta_t$ | `td_delta` |
| $\widehat A_t^{\mathrm{GAE}}$ | `gae` |
| $\log\pi_{\mathrm{old}}(A_t\mid S_t)$ | `old_log_probs` |
| $\log\pi_\theta(A_t\mid S_t)$ | `log_probs` |
| $r_t(\theta)$ | `ratio` |
| $r_t\widehat A_t$ | `surr1` |
| $\operatorname{clip}(r_t,0.8,1.2)\widehat A_t$ | `surr2` |
| $L_{\mathrm{PPO}}$ | `loss_pi` |
| $\nabla_\theta L_{\mathrm{PPO}}$ | produced by `loss_pi.backward()` |

## 15. Why not use the direct loss ten times?

Suppose the program reused the same collected trajectory ten times with:

$$
-\widehat A_t
\log\pi_\theta(A_t\mid S_t).
$$

After the first update, the data still came from $\pi_{\mathrm{old}}$, but the
actor would now be $\pi_\theta$. Repeated unconstrained steps could make the
policy change excessively based on increasingly stale data.

PPO addresses this with:

- the ratio, which explicitly compares new and old action probabilities;
- clipping, which removes incentives for excessive beneficial-looking ratio
  changes;
- in the modern script, approximate-KL monitoring and early stopping.

This is the main reason PPO uses the ratio objective instead of simply applying
the direct log-policy loss repeatedly.

## 16. Final answer

The exact one-step Actor–Critic expression

$$
-\left(
R_t+\gamma V(S_{t+1})-V(S_t)
\right)
\log\pi_\theta(A_t\mid S_t)
$$

does not appear in `code-3-old.py` because:

1. The single TD error is expanded into a GAE advantage.
2. The direct log-policy loss is transformed into PPO's probability-ratio
   surrogate.
3. The ratio is clipped so the same trajectory can be reused more safely.
4. `loss_pi.backward()` differentiates through the ratio and automatically
   recovers the log-policy gradient.

The core connection is:

$$
\boxed{
\nabla_\theta r_t(\theta)
=
r_t(\theta)
\nabla_\theta\log\pi_\theta(A_t\mid S_t)
}
$$

PPO has not removed the policy gradient. It has wrapped that gradient inside a
probability-ratio objective that controls how far repeated updates may move the
policy.
