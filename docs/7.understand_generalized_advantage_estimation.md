# Understanding Generalized Advantage Estimation (GAE)

This note explains the theory and implementation of both Day 3 GAE examples:

- [`code-1-actor-critic-GAE.py`](../rl_learning_demo/day03/code-1-actor-critic-GAE.py)

They implement the same trajectory-batched GAE algorithm. Code 1 presents GAE
directly, while Code 2 is organized as the GAE extension of the trajectory-
batched one-step TD example.

For comparison, the following Day 3 programs use only a single one-step TD
error for each update:

- [`code-1-old.py`](../rl_learning_demo/day03/code-1-old.py)
- [`code-1-actor-critic-online-one-step-td.py`](../rl_learning_demo/day03/code-1-actor-critic-online-one-step-td.py)
- [`code-2-old.py`](../rl_learning_demo/day03/code-2-old.py)
- [`code-2-actor-critic-trajectory-batch-one-step-td.py`](../rl_learning_demo/day03/code-2-actor-critic-trajectory-batch-one-step-td.py)

## 1. Why introduce GAE?

A policy-gradient actor needs to know whether its sampled action was better or
worse than expected. Ideally, it would use the true advantage:

$$
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s)
$$

The true $Q^\pi$ and $V^\pi$ are unknown, so the agent must estimate the
advantage from experience.

Two simple choices have opposite weaknesses:

- A one-step TD error has relatively low variance, but it relies strongly on
  an imperfect critic and can therefore be biased.
- A complete Monte Carlo return uses real rewards from the whole episode and
  less bootstrapping, but normally has much higher variance.

Generalized Advantage Estimation provides a continuous compromise between
these choices. Its parameter $\lambda$ controls how far future TD errors
influence the current advantage.

## 2. Start with the one-step TD error

For transition $t$, first construct the one-step TD target:

$$
y_t^{(1)}
=
R_t
+
\gamma(1-d_t)V_{\mathrm{old}}(S_{t+1})
$$

Here:

- $R_t$ is the reward received after taking $A_t$.
- $\gamma$ is the discount factor.
- $d_t=1$ for a true terminal state and $0$ otherwise.
- $V_{\mathrm{old}}$ means a value estimate captured before the update.

The one-step TD error is:

$$
\delta_t
=
y_t^{(1)}-V_{\mathrm{old}}(S_t)
$$

Therefore:

$$
\boxed{
\delta_t
=
R_t
+
\gamma(1-d_t)V_{\mathrm{old}}(S_{t+1})
-
V_{\mathrm{old}}(S_t)
}
$$

The TD error measures the critic's **value surprise**:

- $\delta_t>0$: the transition was better than expected.
- $\delta_t<0$: the transition was worse than expected.
- $\delta_t\approx0$: the transition was close to the prediction.

A one-step Actor–Critic method uses only $\delta_t$ as the advantage estimate
for action $A_t$.

## 3. GAE combines multiple TD errors

GAE includes the current TD error and discounted future TD errors:

$$
\boxed{
\widehat A_t^{\mathrm{GAE}(\gamma,\lambda)}
=
\delta_t
+
(\gamma\lambda)\delta_{t+1}
+
(\gamma\lambda)^2\delta_{t+2}
+
\cdots
}
$$

It is often described as a multi-step advantage estimator. More precisely,
GAE is a weighted sum of one-step TD residuals.

The recursive form is easier to implement:

$$
\boxed{
\widehat A_t^{\mathrm{GAE}}
=
\delta_t
+
\gamma\lambda(1-d_t)
\widehat A_{t+1}^{\mathrm{GAE}}
}
$$

The calculation must run backward because the advantage at time $t$ depends
on the already-calculated advantage at $t+1$.

## 4. What does lambda control?

The GAE parameter satisfies:

$$
0\leq\lambda\leq1
$$

### When lambda is zero

If $\lambda=0$:

$$
\widehat A_t^{\mathrm{GAE}}=\delta_t
$$

Only the current one-step TD error remains. This is the lowest-horizon GAE
setting and normally has lower variance but greater dependence on the critic.

### When lambda is near one

As $\lambda$ approaches one, later TD errors receive more weight. Credit can
travel much farther backward through the episode.

For a complete episode ending in a true terminal state, $\lambda=1$ makes the
GAE value target equivalent to the Monte Carlo return:

$$
G_t
=
R_t+\gamma R_{t+1}+\gamma^2R_{t+2}+\cdots
$$

This has less bootstrap bias but usually greater variance.

### A common practical choice

The script defaults to:

$$
\gamma=0.98,
\qquad
\lambda=0.95
$$

This preserves substantial multi-step credit assignment while gradually
reducing the influence of very distant TD errors.

## 5. GAE is also a weighted mixture of n-step advantages

An $n$-step advantage estimate is:

$$
\widehat A_t^{(n)}
=
R_t
+
\gamma R_{t+1}
+
\cdots
+
\gamma^{n-1}R_{t+n-1}
+
\gamma^nV(S_{t+n})
-
V(S_t)
$$

GAE can also be understood as an exponentially weighted mixture of these
different $n$-step advantage estimates:

$$
\widehat A_t^{\mathrm{GAE}}
=
(1-\lambda)
\sum_{n=1}^{\infty}
\lambda^{n-1}\widehat A_t^{(n)}
$$

For a finite episode, the sum is truncated at the available horizon, with an
appropriate final bootstrap value when necessary.

This interpretation explains the word **generalized**: GAE does not select
only one fixed return horizon. It blends many horizons.

## 6. From a GAE advantage to a critic target

The advantage is the difference between a return-like target and the value of
the current state:

$$
A_t=V_t^{\mathrm{target}}-V(S_t)
$$

Rearranging gives:

$$
\boxed{
\widehat V_t^{\mathrm{target}}
=
\widehat A_t^{\mathrm{GAE}}
+
V_{\mathrm{old}}(S_t)
}
$$

This target is often called a **GAE return** or **lambda-return-style value
target**.

The critic loss used by the script is:

$$
\boxed{
L_{\mathrm{critic}}(\phi)
=
\frac{1}{N}
\sum_t
\left(
V_\phi(S_t)-\widehat V_t^{\mathrm{target}}
\right)^2
}
$$

Notice the distinction:

- $V_{\mathrm{old}}(S_t)$ inside the target is detached and fixed.
- $V_\phi(S_t)$ on the left side is evaluated with gradients enabled and is
  trained toward that target.

### Endpoint check when lambda is zero

When $\lambda=0$:

$$
\widehat V_t^{\mathrm{target}}
=
\delta_t+V_{\mathrm{old}}(S_t)
$$

Substituting the TD error causes the old current value to cancel:

$$
\widehat V_t^{\mathrm{target}}
=
R_t
+
\gamma(1-d_t)V_{\mathrm{old}}(S_{t+1})
$$

Thus the critic target becomes exactly the one-step TD target.

## 7. Actor loss

The actor uses GAE to decide how the sampled-action probability should change:

$$
L_{\mathrm{actor}}(\theta)
=
-\frac1N
\sum_t
\log\pi_\theta(A_t\mid S_t)
\widehat A_t^{\mathrm{GAE}}
$$

The script also includes a small entropy bonus:

$$
L_{\mathrm{actor}}(\theta)
=
-\frac1N
\sum_t
\log\pi_\theta(A_t\mid S_t)
\widehat A_t^{\mathrm{GAE}}
-
\beta\mathcal H(\pi_\theta)
$$

Entropy measures how spread out the policy's action probabilities are. The
bonus discourages the policy from becoming deterministic too early and helps
maintain exploration.

The effect of the advantage remains intuitive:

- A positive GAE advantage increases the sampled-action probability.
- A negative GAE advantage decreases the sampled-action probability.
- A larger absolute advantage produces a stronger gradient signal.

## 8. Why use old and detached values?

GAE advantages and critic targets should be fixed labels during one optimizer
update. Gradients must not flow through the process that creates them.

The script snapshots value predictions inside `torch.no_grad()`:

```python
with torch.no_grad():
    old_values = self.critic(state_tensor)
    old_next_values = self.critic(next_state_tensor)
```

It then calculates:

```python
td_errors = one_step_td_targets - old_values
gae_advantages = ...
value_targets = gae_advantages + old_values
```

Because this work occurs under `torch.no_grad()`, none of these target tensors
has an autograd graph.

After target construction, the script evaluates the critic again:

```python
values = self.critic(state_tensor)
critic_loss = F.mse_loss(values, value_targets)
```

Only this new `values` tensor receives critic gradients.

Without stop-gradient handling, the optimizer could change both the critic's
prediction and the quantities used as its target. That is not the intended
semi-gradient update.

## 9. Why does the implementation collect an episode first?

The online one-step program can update immediately because $\delta_t$ only
requires the current transition and $V(S_{t+1})$.

GAE at time $t$ also contains future residuals:

$$
\delta_{t+1},\delta_{t+2},\ldots
$$

Therefore, this teaching implementation first collects one complete on-policy
episode:

```text
S_0, A_0, R_0, S_1
S_1, A_1, R_1, S_2
S_2, A_2, R_2, S_3
...
S_(T-1), A_(T-1), R_(T-1), S_T
```

It can then process all TD errors backward. Only after that does it call
`backward()` and update the weights.

Collecting a complete episode is not a requirement of GAE. Production
Actor–Critic algorithms commonly collect a fixed-length rollout, such as 128
or 2048 transitions, bootstrap from its final state, and then calculate GAE
over that rollout.

## 10. Implementation workflow

Both GAE scripts follow the stages below. Small code-organization differences
are identified where they help explain the PyTorch implementation.

### Stage 1: collect one trajectory

`collect_trajectory()` stores:

```python
states
actions
rewards
next_states
terminations
```

The two scripts order these lists differently inside their tuple, but the
stored mathematical data is identical. Code 2 places `next_states` directly
after `states` to emphasize each transition pair $(S_t,S_{t+1})$.

The policy weights remain unchanged during collection, so all actions in that
episode come from the same policy version.

### Stage 2: convert the trajectory to tensors

`update()` converts the Python lists into batched tensors. If the episode has
$N$ transitions, the main shapes are:

```text
states:       [N, state_size]
actions:      [N]
rewards:      [N]
next_states:  [N, state_size]
terminations: [N]
```

### Stage 3: snapshot old values

Before either optimizer step, the critic evaluates all current and next
states with gradients disabled:

```python
old_values = critic(states)
old_next_values = critic(next_states)
```

### Stage 4: calculate all one-step TD errors

The vectorized calculation is:

```python
one_step_td_targets = (
    rewards
    + gamma * (1.0 - terminations) * old_next_values
)
td_errors = one_step_td_targets - old_values
```

This produces:

```text
[delta_0, delta_1, delta_2, ..., delta_(N-1)]
```

### Stage 5: calculate GAE backward

Conceptually, the loop performs:

```python
next_advantage = 0

for t in reversed(range(N)):
    advantage[t] = (
        td_error[t]
        + gamma * gae_lambda
        * (1 - terminated[t])
        * next_advantage
    )
    next_advantage = advantage[t]
```

For a three-transition episode:

$$
\widehat A_2=\delta_2
$$

$$
\widehat A_1
=
\delta_1+(\gamma\lambda)\delta_2
$$

$$
\widehat A_0
=
\delta_0
+
(\gamma\lambda)\delta_1
+
(\gamma\lambda)^2\delta_2
$$

This is the multi-step credit-assignment mechanism.

### Stage 6: construct critic targets

The code implements the requested formula directly:

```python
value_targets = gae_advantages + old_values
```

These targets are not standardized.

### Stage 7: calculate actor and critic losses

The actor distribution and new value predictions are evaluated with gradients.
Code 1 lets `Categorical` select the sampled-action log probabilities:

```python
distribution = Categorical(logits=actor(states))
selected_log_probabilities = distribution.log_prob(actions)
values = critic(states)
```

Code 2 deliberately demonstrates the equivalent vectorized `gather()` form:

```python
action_logits = actor(states)
all_log_probabilities = F.log_softmax(action_logits, dim=1)
selected_log_probabilities = all_log_probabilities.gather(
    dim=1,
    index=actions.unsqueeze(1),
).squeeze(1)
```

For example, if the collected actions are `[1, 0]`, `gather()` selects:

```text
log pi(A=1 | S_0)
log pi(A=0 | S_1)
```

This changes only how the selected log probabilities are extracted. It does
not change the policy-gradient algorithm.

The two losses are then constructed:

```python
actor_loss = -(
    selected_log_probabilities * actor_advantages
).mean() - entropy_coefficient * entropy

critic_loss = F.mse_loss(values, value_targets)
```

### Stage 8: backward and update

```python
actor_optimizer.zero_grad()
critic_optimizer.zero_grad()

actor_loss.backward()
critic_loss.backward()

actor_optimizer.step()
critic_optimizer.step()
```

Remember:

- `backward()` calculates gradients.
- `optimizer.step()` changes network weights.

Each script performs one actor optimizer step and one critic optimizer step per
episode. The trajectory is then discarded, and the next episode collects fresh
experience using the newly updated policy.

## 11. Why standardize actor advantages but not critic targets?

The script standardizes advantages used by the actor:

$$
\widetilde A_t
=
\frac{
\widehat A_t-\operatorname{mean}(\widehat A)
}{
\operatorname{std}(\widehat A)+\epsilon
}
$$

This keeps the actor gradient scale more consistent across episodes and often
improves optimization stability.

The critic target must remain on the real value scale. If GAE were standardized
before constructing the critic target, the target would no longer represent a
meaningful estimate of discounted future reward.

Therefore, the implementation uses:

- standardized `actor_advantages` in the policy loss;
- original `value_targets` in the critic loss.

## 12. Termination versus truncation

Gymnasium returns both `terminated` and `truncated`:

- `terminated=True` means CartPole reached a genuine failure state.
- `truncated=True` usually means the environment time limit was reached.

For a true termination:

$$
V(S_{t+1})=0
$$

For a time-limit truncation, the underlying task may continue, so the script
still bootstraps from the next-state value:

$$
y_t^{(1)}=R_t+\gamma V_{\mathrm{old}}(S_{t+1})
$$

The interaction loop stops for either condition, but only true termination
sets the TD bootstrap mask to zero.

Because this example processes one episode at a time, the backward GAE
accumulator begins at zero beyond the last collected transition. On a
time-limit truncation, the last TD error already includes the final value
bootstrap.

## 13. Gradient clipping and entropy

The script clips actor and critic gradient norms:

```python
torch.nn.utils.clip_grad_norm_(network.parameters(), max_norm=1.0)
```

Gradient clipping limits unusually large updates. It does not change the GAE
formula; it is an optimization safeguard.

The entropy coefficient is set to `0.001`. This small bonus encourages
exploration without dominating the policy-gradient objective.

## 14. Direct comparison of the Day 3 workflows

| Property | Online one-step Code 1 | Trajectory one-step Code 2 | Trajectory GAE Codes 1 and 2 |
|---|---|---|---|
| Actor signal | $\delta_t$ | independent $\delta_t$ values | weighted sequence of $\delta$ values |
| Critic target | one-step TD target | one-step TD target | GAE/lambda-return target |
| Data before update | one transition | one complete episode | one complete episode |
| Actor updates per episode | one per transition | one | one |
| Critic updates per episode | one per transition | one | one |
| Credit horizon | one transition | one transition | multiple transitions |
| Policy during collection | can change every step | fixed for the episode | fixed for the episode |
| Memory use | very small | stores one trajectory | stores one trajectory |
| Backward temporal recursion | no | no | yes |

The trajectory-batched one-step program and the trajectory-GAE program collect
exactly the same kind of experience. Collecting a trajectory alone does not
make an algorithm multi-step.

The difference appears during `update()`:

```text
trajectory-batched one-step Code 2
    delta_t -> actor advantage
    one-step target -> critic target

trajectory-batched GAE Code 2
    delta_t -> backward GAE recursion -> actor advantage
    GAE advantage + old value -> critic target
```

### Are the two GAE scripts different algorithms?

No. [`code-1-actor-critic-GAE.py`](../rl_learning_demo/day03/code-1-actor-critic-GAE.py)
and
[`code-2-actor-critic-trajectory-GAE.py`](../rl_learning_demo/day03/code-2-actor-critic-trajectory-GAE.py)
use the same:

- one-trajectory-per-episode collection;
- one-step TD-error formula;
- backward GAE recurrence;
- detached target $\widehat A_t^{\mathrm{GAE}}+V_{\mathrm{old}}(S_t)$;
- standardized actor advantages;
- entropy bonus and gradient clipping;
- one actor and one critic optimizer step per episode.

Their main difference is presentation. Code 2 mirrors the structure of the
trajectory-batched one-step Code 2 and uses `log_softmax(...).gather(...)` to
show explicitly how batched sampled-action log probabilities are selected.

## 15. GAE versus a fixed n-step return

A fixed n-step method always uses one chosen horizon $n$:

$$
R_t+\gamma R_{t+1}+\cdots+\gamma^nV(S_{t+n})
$$

GAE blends information from many possible horizons through $\lambda$. It does
not mean that the algorithm updates once after every possible horizon. The
mixture is produced efficiently through one backward recursion.

## 16. Common misunderstandings

### “GAE removes the critic.”

No. GAE is constructed from TD errors, and those TD errors require critic
values. The quality of the critic still matters.

### “GAE is the critic loss.”

No. GAE produces an advantage estimate. The implementation then uses that
estimate to construct a critic target. MSE between the new value prediction and
that fixed target is the critic loss.

### “GAE means there is no one-step TD error.”

No. GAE is built directly from a sequence of one-step TD errors.

### “The actor and critic must use identical processed advantages.”

No. The actor may use standardized advantages for optimization. The critic
must retain value targets on the original return scale.

### “backward() changes the policy.”

No. `backward()` calculates gradients. The weights change only when the
corresponding optimizer calls `step()`.

### “GAE always requires a complete episode.”

No. It can be calculated over a fixed-length rollout by bootstrapping from the
value of the state after that rollout.

## 17. Compact pseudocode

```text
initialize actor parameters theta
initialize critic parameters phi

for each episode:
    collect one on-policy trajectory

    with gradients disabled:
        evaluate V_old(S_t) and V_old(S_(t+1))

        for every t:
            delta_t = (
                R_t
                + gamma * (1 - terminated_t) * V_old(S_(t+1))
                - V_old(S_t)
            )

        gae = 0
        for t from the final transition back to zero:
            gae = delta_t + gamma * lambda * (1 - terminated_t) * gae
            advantage_t = gae
            value_target_t = advantage_t + V_old(S_t)

    actor_loss = mean(-log pi_theta(A_t | S_t) * advantage_t)
    critic_loss = mean((V_phi(S_t) - value_target_t)^2)

    calculate actor and critic gradients
    update theta and phi
```


Both scripts accept the same `--episodes`, `--seed`, `--gamma`,

Useful experiments are:

- `--gae-lambda 0`: one-step TD advantages and one-step critic targets.
- `--gae-lambda 0.5`: a shorter multi-step mixture.
- `--gae-lambda 0.95`: the default practical compromise.
- `--gae-lambda 1`: Monte Carlo-like targets for terminal episodes.

Compare the learning speed and variability across several random seeds rather
than judging a setting from only one training run.

## 19. Final mental model

The one-step TD error asks:

> Was this single transition better or worse than expected?

GAE asks:

> After combining the surprises from this transition and later transitions,
> how good was this action relative to the critic's expectation?

The complete chain is:

```text
rewards and old values
        |
        v
one-step TD errors
        |
        v
backward GAE recursion
        |
        +--> actor advantages
        |
        +--> advantage + old value --> critic targets
```

The central equations are:

$$
\boxed{
\delta_t
=
R_t
+
\gamma(1-d_t)V_{\mathrm{old}}(S_{t+1})
-
V_{\mathrm{old}}(S_t)
}
$$

$$
\boxed{
\widehat A_t^{\mathrm{GAE}}
=
\delta_t
+
\gamma\lambda(1-d_t)
\widehat A_{t+1}^{\mathrm{GAE}}
}
$$

$$
\boxed{
\widehat V_t^{\mathrm{target}}
=
\widehat A_t^{\mathrm{GAE}}
+
V_{\mathrm{old}}(S_t)
}
$$

The actor learns from the GAE advantage. The critic learns from the detached
GAE value target.
