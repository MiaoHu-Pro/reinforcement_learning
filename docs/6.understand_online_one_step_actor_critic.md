# Understanding online one-step Actor–Critic

This note explains the theory and update workflow of
[`code-1-old.py`](../rl_learning_demo/day03/code-1-old.py).

The modern Gymnasium rewrite is
[`code-1-actor-critic-online-one-step-td.py`](../rl_learning_demo/day03/code-1-actor-critic-online-one-step-td.py).

## 1. What algorithm does the old program implement?

The program implements an **online, one-step Actor–Critic algorithm** for
CartPole.

It has two neural networks:

- The **actor**, `PolicyNet`, represents the policy
  $\pi_\theta(a \mid s)$.
- The **critic**, `ValueNet`, approximates the state value
  $V_\phi(s)$.

Here, $\theta$ denotes the actor parameters and $\phi$ denotes the critic
parameters.

The important feature of this example is its update timing:

1. Observe the current state $S_t$.
2. Sample one action $A_t$ from the actor.
3. Execute the action and receive $R_t$ and $S_{t+1}$.
4. Immediately calculate a one-step TD error.
5. Immediately call `backward()` and update both networks.
6. Continue from $S_{t+1}$.

The program does **not** wait until the episode finishes before learning.

## 2. The actor

The actor receives a state and produces a probability for each action:

$$
\pi_\theta(a \mid s) = P(A_t=a \mid S_t=s)
$$

CartPole has two possible actions, so the output is similar to:

```text
[0.35, 0.65]
```

This means that the actor currently assigns probability $0.35$ to action 0
and probability $0.65$ to action 1.

The old program samples an action with:

```python
probs = self.pi(torch.tensor(state).unsqueeze(0)).squeeze(0)
distribution = Categorical(probs)
action = distribution.sample().item()
```

Sampling is important during training because the agent must explore. It does
not always select the action with the largest probability.

## 3. The critic

The critic estimates how much discounted future reward is expected from a
state when the actor's current policy is followed:

$$
V^{\pi_\theta}(s)
=
\mathbb{E}_{\pi_\theta}
\left[
\sum_{k=0}^{\infty}\gamma^k R_{t+k}
\;\middle|\;
S_t=s
\right]
$$

The critic does not directly choose an action. Its job is to provide a
learning signal that tells the actor whether a sampled action produced an
outcome that was better or worse than expected.

## 4. The one-step TD target

After taking an action, the agent observes one transition:

$$
(S_t, A_t, R_t, S_{t+1})
$$

It constructs the one-step temporal-difference target:

$$
y_t
=
R_t + \gamma(1-d_t)V_\phi(S_{t+1})
$$

where:

- $R_t$ is the immediate reward.
- $\gamma$ is the discount factor.
- $d_t=1$ for a true terminal state and $0$ otherwise.
- $V_\phi(S_{t+1})$ estimates the reward available after the next state.

In the old program, this is called `target`:

```python
target = reward + self.gamma * self.v(next_state) * (1 - done)
```

If the transition is not terminal:

$$
y_t = R_t + \gamma V_\phi(S_{t+1})
$$

If it is terminal, there are no future rewards to bootstrap from:

$$
y_t = R_t
$$

This use of $V_\phi(S_{t+1})$ is called **bootstrapping**. The critic improves
its current prediction using another prediction.

## 5. The one-step TD error

The TD error is the difference between the new target and the critic's current
prediction:

$$
\delta_t
=
y_t - V_\phi(S_t)
$$

Substituting the target gives:

$$
\delta_t
=
R_t
+ \gamma(1-d_t)V_\phi(S_{t+1})
- V_\phi(S_t)
$$

This also shows why the comment in the old code is mathematically valid:

$$
y_t = \delta_t + V_\phi(S_t)
$$

However, `target` and `delta` are different quantities:

- `target` is the value that $V_\phi(S_t)$ should approach.
- `delta` is the prediction error and the actor's advantage estimate.

### Interpreting the sign

If $\delta_t > 0$, the result was better than the critic expected. The actor
should make $A_t$ more likely in $S_t$.

If $\delta_t < 0$, the result was worse than expected. The actor should make
$A_t$ less likely.

If $\delta_t \approx 0$, the outcome was close to the critic's expectation, so
the actor receives only a small update.

## 6. Why is the TD error an advantage estimate?

The true advantage function is:

$$
A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)
$$

It measures how much better action $a$ is than the policy's usual expected
result in state $s$.

For one observed transition, the quantity

$$
R_t + \gamma V_\phi(S_{t+1})
$$

approximates $Q^\pi(S_t,A_t)$. Therefore:

$$
\delta_t
=
R_t + \gamma V_\phi(S_{t+1}) - V_\phi(S_t)
\approx
A^\pi(S_t,A_t)
$$

This is why one-step Actor–Critic can use $\delta_t$ to train the actor.

## 7. Critic loss

The critic should move $V_\phi(S_t)$ toward the TD target $y_t$. The old
program uses mean squared error:

$$
L_{\text{critic}}(\phi)
=
\left(V_\phi(S_t)-y_t\right)^2
$$

In code:

```python
value = self.v(state)
loss_v = F.mse_loss(value, target)
```

Minimizing this loss makes the critic a better predictor. A better critic then
provides more useful TD errors to the actor.

## 8. Actor loss

The policy-gradient update should increase the probability of actions with a
positive advantage and decrease the probability of actions with a negative
advantage.

For one transition, the actor loss is:

$$
L_{\text{actor}}(\theta)
=
-\log \pi_\theta(A_t \mid S_t)\,\delta_t
$$

The old program calculates it as:

```python
delta = target - value
loss_pi = -torch.log(action_prob) * delta.detach().item()
```

Gradient descent minimizes the loss:

- When $\delta_t>0$, minimizing the loss increases
  $\pi_\theta(A_t\mid S_t)$.
- When $\delta_t<0$, minimizing the loss decreases
  $\pi_\theta(A_t\mid S_t)$.

## 9. Why must the target and TD error be detached?

The actor and critic solve related but separate optimization problems.

### Detaching the TD target

The critic treats $y_t$ as a fixed training label. Gradients should change
$V_\phi(S_t)$, but they should not flow through the target into
$V_\phi(S_{t+1})$.

The old program contains:

```python
target.detach()
```

This is a bug because `detach()` is not an in-place operation. It returns a new
tensor. The result must be assigned:

```python
target = target.detach()
```

An even clearer form is:

```python
with torch.no_grad():
    target = reward + gamma * critic(next_state) * (1 - terminated)
```

Without detaching the target, the critic optimizer tries to change both
$V_\phi(S_t)$ and the prediction used as its label, $V_\phi(S_{t+1})$.

### Detaching the TD error in the actor loss

For the actor update, $\delta_t$ is a numerical learning signal. The actor loss
should update only $\theta$, not the critic parameters $\phi$.

Conceptually:

```python
actor_loss = -log_probability * td_error.detach()
```

The old code uses `delta.detach().item()`. This prevents critic gradients, but
converting to a Python number with `.item()` is unnecessary. `detach()` alone
is sufficient and keeps the expression as a tensor.

## 10. Exactly when are gradients and weights updated?

For every environment step, the old program calls:

```python
agent.update(state, next_state, reward, probs[action], done)
```

Inside `update()` the sequence is:

```text
one transition
    |
    +--> calculate TD target and TD error
    |
    +--> calculate critic loss
    |
    +--> calculate actor loss
    |
    +--> zero_grad()
    |
    +--> critic loss backward()
    |
    +--> actor loss backward()
    |
    +--> actor optimizer step()
    |
    +--> critic optimizer step()
```

The meanings of the PyTorch operations are:

- `zero_grad()` removes gradients left from the previous update.
- `backward()` calculates gradients but does not change any weights.
- `optimizer.step()` changes the weights using those gradients.

If an episode has 25 transitions, this program normally performs:

- 25 actor backward passes and 25 actor optimizer steps.
- 25 critic backward passes and 25 critic optimizer steps.

The episode is one complete trajectory, but that trajectory is not stored as a
batch. Each transition is consumed immediately and then discarded.

## 11. Full episode workflow

The complete workflow is:

```text
reset environment -> S_0

S_0 -> sample A_0 -> receive R_0, S_1 -> update actor and critic
S_1 -> sample A_1 -> receive R_1, S_2 -> update actor and critic
S_2 -> sample A_2 -> receive R_2, S_3 -> update actor and critic
...
S_(T-1) -> sample A_(T-1) -> receive R_(T-1), S_T -> update

episode ends
```

The weights can therefore change many times during one trajectory. Later
actions in the same episode can be sampled from a slightly newer policy than
earlier actions.

## 12. Why update online?

Online one-step learning has several advantages:

- It can learn before the episode finishes.
- It needs very little trajectory memory.
- It responds quickly to new transitions.
- Bootstrapping usually reduces variance relative to full Monte Carlo returns.

It also has disadvantages:

- A one-step target depends heavily on the critic's current accuracy.
- Early critic estimates can be poor and create biased actor updates.
- Updating from one transition at a time produces noisy gradients.
- Highly correlated consecutive transitions can reduce training stability.

This gives the familiar bias–variance trade-off:

- Monte Carlo methods have low bootstrap bias but high variance.
- One-step TD methods generally have more bias but lower variance.

## 13. `done` in old Gym versus Gymnasium

The old Gym API returns one `done` flag:

```python
next_state, reward, done, info = env.step(action)
```

Gymnasium separates this into two conditions:

```python
next_state, reward, terminated, truncated, info = env.step(action)
```

- `terminated=True` means the task reached a genuine terminal state.
- `truncated=True` means an external limit, commonly the time limit, stopped
  the episode.

The interaction loop stops for either condition:

```python
done = terminated or truncated
```

However, the TD target should normally remove bootstrapping only for a true
termination:

$$
y_t
=
R_t + \gamma(1-\text{terminated}_t)V_\phi(S_{t+1})
$$

A time-limit truncation does not imply that the underlying state has zero
future value.

## 14. Other differences in the modern rewrite

The modern script makes several implementation improvements:

- It imports `gymnasium` instead of unmaintained `gym`.
- It uses `CartPole-v1` instead of obsolete `CartPole-v0`.
- It handles the new `reset()` and `step()` return values.
- It derives state and action sizes from the environment.
- It explicitly uses `torch.float32` tensors.
- The actor returns logits and uses `Categorical(logits=...)` for numerical
  stability.
- It uses `torch.no_grad()` when constructing the critic target.
- It uses `td_error.detach()` for the actor without converting it to a Python
  number.
- It closes the environment and saves the plot without requiring a GUI.
- It reports actor loss, critic loss, and mean TD error during training.

The central algorithm remains the same: **one transition followed by one
one-step TD Actor–Critic update**.

## 15. Comparison with the earlier examples

| Program type | Actor learning signal | Wait for episode end? | Update frequency |
|---|---|---:|---:|
| REINFORCE | Monte Carlo return $G_t$ | Yes | Once per episode |
| REINFORCE with value baseline | $G_t-V_\phi(S_t)$ | Yes | Once per episode |
| This online Actor–Critic | one-step TD error $\delta_t$ | No | Once per transition |
| n-step Actor–Critic | n-step bootstrapped advantage | No | Once per short rollout |

The major transition from REINFORCE to this example is replacing the complete
Monte Carlo return with a bootstrapped one-step target.

## 16. Compact pseudocode

```text
initialize actor parameters theta
initialize critic parameters phi

for each episode:
    observe initial state S_t

    while the episode is not finished:
        sample A_t from pi_theta(. | S_t)
        execute A_t
        observe R_t and S_(t+1)

        y_t = R_t + gamma * (1 - terminated) * V_phi(S_(t+1))
        delta_t = y_t - V_phi(S_t)

        critic_loss = (V_phi(S_t) - stop_gradient(y_t))^2
        actor_loss = -log pi_theta(A_t | S_t) * stop_gradient(delta_t)

        calculate actor and critic gradients
        update theta and phi

        S_t = S_(t+1)
```

`stop_gradient(...)` is the mathematical role played by PyTorch's
`detach()` or `torch.no_grad()`.

## 17. Final mental model

The critic asks:

> After seeing one reward and my estimate of the next state, was my estimate
> of the current state correct?

The actor asks:

> Was the action I sampled better or worse than the critic expected?

The one-step TD error answers both questions:

$$
\boxed{
\delta_t
=
R_t
+ \gamma(1-d_t)V_\phi(S_{t+1})
- V_\phi(S_t)
}
$$

The critic reduces this error. The actor uses its sign and magnitude to change
the probability of the sampled action.
