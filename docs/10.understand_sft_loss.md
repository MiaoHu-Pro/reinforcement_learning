# Understanding the SFT loss in `1-SFT-fixed.py`

## 1. What kind of SFT does this script perform?

`rl_learning_demo/day06_InstructGPT/1-SFT-fixed.py` performs supervised causal-language-model fine-tuning on complete shopping-review texts.

It is **not instruction-response SFT**, because the training data does not contain a structure such as:

- instruction or user prompt;
- assistant answer;
- a mask separating the prompt tokens from the answer tokens.

Instead, each `review` is treated as one continuous text sequence. The model learns to predict every next token in that review. This is more precisely described as **causal language-model fine-tuning** or **domain-adaptive SFT** on labelled text examples, although the dataset's sentiment label is removed and is not used by this SFT objective.

## 2. Where do the labels come from?

The `tokenize()` function produces `input_ids` and `attention_mask`:

```python
return tokenizer(
    batch["review"],
    truncation=True,
    max_length=model.config.n_positions,
    return_token_type_ids=False
)
```

It does not explicitly create `labels`. The labels are created later by:

```python
data_collator = DataCollatorForLanguageModeling(
    tokenizer,
    mlm=False
)
```

Because `mlm=False`, this is causal-language-model training. Conceptually, the collator performs:

```python
labels = input_ids.clone()
labels[padding_positions] = -100
```

The value `-100` is PyTorch cross-entropy's ignore index. Consequently, padding tokens do not contribute to the loss.

## 3. How is next-token loss calculated?

Suppose one tokenized review is:

```text
[CLS]  这  本  书  很  好  [SEP]
```

For a causal language model, the logits and labels are shifted internally:

| Model receives the prefix ending at | Target token | Included in loss? |
|---|---|---|
| `[CLS]` | `这` | Yes |
| `[CLS] 这` | `本` | Yes |
| `[CLS] 这 本` | `书` | Yes |
| `[CLS] 这 本 书` | `很` | Yes |
| `[CLS] 这 本 书 很` | `好` | Yes |
| `[CLS] 这 本 书 很 好` | `[SEP]` | Yes |
| Padding positions | `[PAD]` | No (`label = -100`) |

Therefore, the first input token is used as context but is not itself predicted. Every subsequent non-padding token, including the final `[SEP]`, is a prediction target.

For tokens

$$
x_0, x_1, \ldots, x_T,
$$

the sequence loss is conceptually:

$$
L_{\mathrm{CLM}}(\theta)
=
-\frac{1}{T}
\sum_{t=0}^{T-1}
\log \pi_\theta(x_{t+1}\mid x_0,\ldots,x_t).
$$

For a padded batch, Transformers averages over the valid target positions whose labels are not `-100`.

This shift happens inside `AutoModelForCausalLM` when the following code passes `labels` to the model:

```python
outputs = model(**batch)
loss = outputs.loss
```

## 4. Does the script calculate loss over all tokens?

Yes, with two qualifications:

1. It calculates a **next-token loss at every valid target position**, rather than losses between every possible pair of tokens.
2. Padding tokens and the first sequence token do not become prediction targets.

There is no answer-only mask. Tokens that might be considered a prompt and tokens that might be considered an answer would all contribute to the loss because the script does not know where one ends and the other begins.

## 5. How is instruction SFT different?

Instruction SFT normally constructs a sequence resembling:

```text
<user prompt tokens> <assistant answer tokens>
```

It commonly masks the user/prompt portion:

```text
input_ids: prompt_token_1 ... prompt_token_N answer_token_1 ... answer_token_M
labels:    -100           ... -100           answer_token_1 ... answer_token_M
```

Its loss is then:

$$
L_{\mathrm{answer}}(\theta)
=
-\frac{1}{M}
\sum_{t=1}^{M}
\log \pi_\theta(a_t\mid p,a_{<t}),
$$

where $p$ is the complete prompt and $a_{<t}$ contains the earlier answer tokens.

The prompt still enters the model and conditions the answer, but its tokens have label `-100`, so prediction errors on the prompt do not update the model.

| Property | Current `1-SFT-fixed.py` | Answer-only instruction SFT |
|---|---|---|
| Training record | One complete review | Prompt plus assistant answer |
| Prompt/answer boundary | None | Explicit |
| Loss-bearing tokens | All non-padding next-token targets | Assistant-answer targets only |
| Padding loss | Ignored | Ignored |
| Main purpose | Adapt language modelling to review text | Teach instruction following and answer behaviour |

## 6. Why can the current model still generate text?

The pretrained GPT-2 already knows causal next-token prediction. Fine-tuning it on shopping reviews changes its token probabilities toward the language, style, and patterns of that domain.

For example, after seeing many complete reviews beginning with expressions such as `这本书`, the model may become better at continuing:

```text
这本书真是 ...
```

However, this does not by itself teach the model to follow arbitrary user instructions. It teaches review-style continuation because that is the supervised behaviour demonstrated by the dataset.

## 7. Relationship to the later RLHF stages

In this educational pipeline:

1. `1-SFT-fixed.py` adapts the base causal LM to shopping-review text.
2. `2-RM-fixed.py` trains a reward model to score generated text using the sentiment labels.
3. `3-PPO-fixed.py` updates the SFT policy to produce continuations receiving higher reward while using a KL penalty to remain close to the SFT reference policy.

This demonstrates the mechanics of an InstructGPT-like SFT → reward model → PPO pipeline, but it is not a complete instruction-following dataset setup. For genuine instruction SFT, the first stage needs prompt/answer examples and answer-only label masking.

## Summary

The current SFT objective is:

$$
\boxed{
\text{predict every next non-padding token in the complete review}
}
$$

It is not:

$$
\boxed{
\text{calculate loss only on assistant-answer tokens}
}
$$

To obtain answer-only instruction SFT, the dataset and collator must explicitly identify the prompt boundary and replace the corresponding prompt labels with `-100`.
