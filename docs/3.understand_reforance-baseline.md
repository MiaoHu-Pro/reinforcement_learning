# Understanding REINFORCE and a learned value baseline

This note explains the theory and implementation of:

- [`code-4-reinforce-policy-gradient-step-by-step.py`](../rl_learning_demo/day02/code-4-reinforce-policy-gradient-step-by-step.py): reward-to-go REINFORCE;
- [`code-5-reinforce-policy-gradient-value-baseline.py`](../rl_learning_demo/day02/code-5-reinforce-policy-gradient-value-baseline.py): REINFORCE with a learned
  neural-network state-value baseline.

Both programs use CartPole-v1 and collect one complete trajectory per episode.
The policy weights remain fixed while a trajectory is collected. The networks
are updated only after the episode ends.

## 1. Main difference

The policy-gradient weight applied to an action is the central difference:

```text
code-4-reinforce-policy-gradient-step-by-step.py:  G_t

code-5-reinforce-policy-gradient-value-baseline.py:  A_t = G_t - V_phi(S_t)
```

`code-4-reinforce-policy-gradient-step-by-step.py` asks:

> How much discounted reward followed action `A_t`?

`code-5-reinforce-policy-gradient-value-baseline.py` asks a more informative question:

> Was the observed return better or worse than the return normally expected
> from state `S_t`?

The value network provides that expectation.

## 2. Common notation

| Symbol | Meaning |
|---|---|
| `S_t` | state at time `t` |
| `A_t` | action selected at time `t` |
| `R_t` | reward received after selecting `A_t` |
| `pi_theta(a|s)` | policy network's probability of action `a` in state `s` |
| `theta` | policy-network parameters |
| `gamma` | discount factor; `0.98` in both scripts |
| `G_t` | sampled discounted return from time `t` onward |
| `V^pi(s)` | true expected return from state `s` under policy `pi` |
| `V_phi(s)` | neural-network approximation of `V^pi(s)` |
| `phi` | value-network parameters |
| `A_t` | advantage: `G_t - V_phi(S_t)` |

Do not confuse action `A_t` with advantage `A_t`. They often use the same
letter in reinforcement-learning notation. When necessary, this note writes
the advantage as `Adv_t`.

## 3. A trajectory and an episode

One episode produces one realized trajectory:

```text
tau = (S_0, A_0, R_0, S_1, A_1, R_1, ..., S_T)
```

The stochastic policy defines a distribution over many possible trajectories,
but a single episode samples only one of them:

```text
All possible trajectories under pi_theta
                    │
                    │ run one episode
                    ▼
          one realized trajectory tau
```

Both scripts use the same training rhythm:

```text
Episode k
  1. collect one complete trajectory using policy weights theta_k
  2. calculate reward-to-go values
  3. construct the loss
  4. call backward()
  5. call optimizer.step()
  6. begin episode k+1 using updated weights theta_(k+1)
```

## 4. Policy-gradient objective

The policy should maximize expected return:

$$
J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[G_0]
$$

The policy changes the probability of a trajectory through its action
probabilities. Using the log-derivative identity gives a Monte Carlo gradient
estimator involving:

$$
\nabla_\theta \log \pi_\theta(A_t|S_t)
$$

The policy-gradient idea is:

```text
positive learning weight
    → increase the probability of the sampled action

negative learning weight
    → decrease the probability of the sampled action
```

PyTorch optimizers minimize a loss, so the implementation uses a minus sign.

## 5. Reward-to-go

The reward-to-go from time `t` is:

$$
G_t = R_t + \gamma R_{t+1} + \gamma^2 R_{t+2} + \cdots
$$

It can be computed efficiently backward:

$$
G_t = R_t + \gamma G_{t+1}
$$

For example, if:

```python
rewards = [1.0, 1.0, 1.0]
gamma = 0.9
```

then:

```text
G_2 = 1 + 0.9 × 0    = 1.00
G_1 = 1 + 0.9 × 1.00 = 1.90
G_0 = 1 + 0.9 × 1.90 = 2.71
```

The result in chronological order is:

```python
returns = [2.71, 1.90, 1.00]
```

Each action is paired with its own future return:

```text
log pi(A_0|S_0) × G_0
log pi(A_1|S_1) × G_1
log pi(A_2|S_2) × G_2
```

An action cannot affect rewards received before that action, so excluding past
rewards reduces unnecessary gradient variance.

## 6. `code-4-reinforce-policy-gradient-step-by-step.py`: REINFORCE without a baseline

### 6.1 Policy network

`PolicyNet` maps the four-dimensional CartPole state to two logits:

```python
hidden = F.relu(self.hidden(states))
return self.output(hidden)
```

The outputs are logits rather than probabilities. PyTorch's `Categorical`
distribution converts them internally using a stable softmax:

```python
distribution = Categorical(logits=self.policy(state_tensor))
```

### 6.2 Action selection

During trajectory collection:

```python
with torch.no_grad():
    logits = self.policy(state_tensor)

action = Categorical(logits=logits).sample()
```

`torch.no_grad()` is appropriate here because the environment interaction is
not differentiable. The code saves the state and sampled action, then evaluates
them again during the update.

### 6.3 Collecting the trajectory

`collect_trajectory()` stores:

```python
states.append(state)
actions.append(action)
rewards.append(float(reward))
```

The loop ends when either Gymnasium signal becomes true:

```python
while not (terminated or truncated):
```

- `terminated=True`: a terminal condition belonging to the task occurred;
- `truncated=True`: an external limit, normally the 500-step time limit,
  stopped the episode.

### 6.4 Building the loss backward

`code-4-reinforce-policy-gradient-step-by-step.py` deliberately uses an explicit reverse loop:

```python
return_from_t = 0.0

for reward, state, action in zip(
    reversed(rewards),
    reversed(states),
    reversed(actions),
):
    return_from_t = reward + self.gamma * return_from_t

    distribution = Categorical(logits=self.policy(state_tensor))
    selected_log_probability = distribution.log_prob(action_tensor)
    loss_terms.append(-return_from_t * selected_log_probability)
```

This creates one term per time step:

$$
L_t = -G_t \log \pi_\theta(A_t|S_t)
$$

The complete episode loss is:

```python
loss = torch.stack(loss_terms).mean()
```

or mathematically:

$$
L_{policy}^{code4}
= -\frac{1}{T}\sum_{t=0}^{T-1}
G_t \log \pi_\theta(A_t|S_t)
$$

### 6.5 Backpropagation and update

```python
self.optimizer.zero_grad()
loss.backward()
self.optimizer.step()
```

These operations mean:

1. `zero_grad()` clears gradients from the previous episode.
2. `backward()` calculates the gradient of the loss with respect to `theta`.
3. `step()` changes the policy weights.

`backward()` does not update weights by itself. The update occurs only at
`optimizer.step()`.

### 6.6 Why can plain REINFORCE be noisy?

`G_t` is one random sample of the future return. Its magnitude depends on:

- the random initial state;
- all sampled future actions;
- environment randomness;
- episode length.

Two similar states can therefore receive very different sampled returns. The
gradient remains useful on average, but individual episode updates can have
high variance.

## 7. State-value function

The true state-value function under policy `pi` is:

$$
V^\pi(s)
= \mathbb{E}_\pi[G_t \mid S_t=s]
$$

In words:

> `V^pi(s)` is the expected future discounted return when starting from state
> `s` and then following policy `pi`.

The true expectation is unknown. `code-5-reinforce-policy-gradient-value-baseline.py` approximates it with a neural
network:

$$
V_\phi(s) \approx V^\pi(s)
$$

`ValueNet` has:

```text
4 state inputs → 128 hidden units → 1 scalar value
```

Its output is not an action probability. It is a prediction of future return.

## 8. Baseline and advantage

Instead of weighting the policy gradient by raw `G_t`, `code-5-reinforce-policy-gradient-value-baseline.py` uses:

$$
Adv_t = G_t - V_\phi(S_t)
$$

Interpretation:

```text
Adv_t > 0
    observed return was better than expected
    → increase probability of A_t

Adv_t < 0
    observed return was worse than expected
    → decrease probability of A_t

Adv_t ≈ 0
    result was close to expectation
    → make only a small policy update
```

Example:

```text
G_t = 20

If V(S_t) = 5:   advantage = +15  → strong positive update
If V(S_t) = 18:  advantage =  +2  → small positive update
If V(S_t) = 25:  advantage =  -5  → decrease action probability
```

The baseline provides context. A return of 20 may be excellent in one state
and disappointing in another state.

## 9. Does the baseline introduce policy-gradient bias?

This point requires precise language.

The learned network `V_phi(s)` can be a biased or inaccurate approximation of
the true value function. However, subtracting an **action-independent** baseline
does not bias the expected policy gradient:

$$
\mathbb{E}_{A\sim\pi}
\left[\nabla_\theta\log\pi_\theta(A|S)b(S)\right] = 0
$$

The reason is:

$$
\sum_a \pi_\theta(a|s)
\nabla_\theta\log\pi_\theta(a|s)
= \sum_a \nabla_\theta\pi_\theta(a|s)
= \nabla_\theta 1
= 0
$$

Therefore:

- the sampled update changes because the baseline changes its variance;
- the expected policy-gradient direction remains unchanged;
- the baseline must not depend on the sampled action;
- gradients from the policy loss must not train the baseline to manipulate the
  policy objective.

The code enforces the last rule with `detach()`.

Bootstrapped value targets such as `R_t + gamma*V(S_(t+1))` introduce a
different bias-variance trade-off. `code-5-reinforce-policy-gradient-value-baseline.py` does not use bootstrapping; it
uses complete Monte Carlo returns `G_t`.

## 10. `code-5-reinforce-policy-gradient-value-baseline.py`: REINFORCE with a learned baseline

### 10.1 Two separate networks

```python
self.policy = PolicyNet(state_size, action_size)
self.value = ValueNet(state_size)
```

They have separate parameters and optimizers:

```python
self.policy_optimizer = optim.Adam(self.policy.parameters(), lr=0.002)
self.value_optimizer = optim.Adam(self.value.parameters(), lr=0.002)
```

Their roles are different:

| Network | Input | Output | Learning purpose |
|---|---|---|---|
| Policy `pi_theta` | state | action logits | choose actions that lead to higher return |
| Value `V_phi` | state | one scalar | predict expected future return |

### 10.2 Batched tensors

After one trajectory with `T` steps is collected, `update()` creates:

| Tensor | Shape | Meaning |
|---|---:|---|
| `state_tensor` | `[T, 4]` | all states in the trajectory |
| `action_tensor` | `[T]` | sampled action at each state |
| `returns` | `[T]` | Monte Carlo `G_t` values |
| policy logits | `[T, 2]` | left/right scores |
| `selected_log_probabilities` | `[T]` | `log pi(A_t|S_t)` |
| `value_estimates` | `[T]` | `V_phi(S_t)` |
| `advantages` | `[T]` | `G_t - V_phi(S_t)` |

The policy and value networks evaluate every stored state in a batch:

```python
distribution = Categorical(logits=self.policy(state_tensor))
selected_log_probabilities = distribution.log_prob(action_tensor)
value_estimates = self.value(state_tensor)
```

### 10.3 Advantage calculation

```python
advantages = returns - value_estimates
```

At this point, `advantages` is connected to the value network's autograd graph.
That connection is useful for understanding where the values came from, but it
must not be followed when calculating policy gradients.

### 10.4 Policy loss and `detach()`

```python
policy_loss = -(
    selected_log_probabilities * advantages.detach()
).mean()
```

The policy loss is:

$$
L_{policy}^{code5}
= -\frac{1}{T}\sum_{t=0}^{T-1}
\log\pi_\theta(A_t|S_t)
\operatorname{stopgrad}(G_t-V_\phi(S_t))
$$

`advantages.detach()` returns the same numerical values but removes their
connection to `ValueNet` for this loss.

Without `detach()`, minimizing the policy loss could change the value network
merely to make the policy loss smaller. That is not the value network's job and
would violate the intended baseline derivation.

With `detach()`:

```text
policy_loss.backward()
    → calculates gradients for PolicyNet
    → does not calculate policy-loss gradients for ValueNet
```

### 10.5 Value-network loss

The Monte Carlo return is used as a supervised regression target:

```python
value_loss = F.mse_loss(value_estimates, returns)
```

Mathematically:

$$
L_{value}
= \frac{1}{T}\sum_{t=0}^{T-1}
\left(V_\phi(S_t)-G_t\right)^2
$$

This loss trains the value network to answer:

> Given `S_t`, what return should the current policy expect from this point?

Because `G_t` is a noisy single-trajectory sample, the value loss may fluctuate
substantially. It does not need to decrease monotonically every episode.

### 10.6 Backward and optimizer workflow

```python
self.policy_optimizer.zero_grad()
self.value_optimizer.zero_grad()

policy_loss.backward()
value_loss.backward()

self.policy_optimizer.step()
self.value_optimizer.step()
```

The workflow is:

```text
policy_loss.backward()
    → fills PolicyNet parameter .grad values

value_loss.backward()
    → fills ValueNet parameter .grad values

policy_optimizer.step()
    → changes theta

value_optimizer.step()
    → changes phi
```

There is one policy update and one value update after each completed trajectory.

## 11. Complete `code-5-reinforce-policy-gradient-value-baseline.py` episode timeline

```text
Start episode k with policy theta_k and value parameters phi_k
                           │
                           ▼
Collect one trajectory with theta_k
    - use no_grad()
    - do not update either network
                           │
                           ▼
Calculate all Monte Carlo returns G_t
                           │
                           ▼
Policy forward pass: log pi_theta(A_t|S_t)
Value forward pass:  V_phi(S_t)
                           │
                           ▼
Calculate advantages G_t - V_phi(S_t)
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
Policy loss with                    Value MSE loss
detached advantages                 against G_t
             │                           │
             ▼                           ▼
policy backward()                  value backward()
             │                           │
             ▼                           ▼
update theta                       update phi
             └─────────────┬─────────────┘
                           ▼
Collect episode k+1 with the updated policy
```

## 12. `code-4-reinforce-policy-gradient-step-by-step.py` versus `code-5-reinforce-policy-gradient-value-baseline.py`

| Feature | `code-4-reinforce-policy-gradient-step-by-step.py` | `code-5-reinforce-policy-gradient-value-baseline.py` |
|---|---|---|
| Algorithm | reward-to-go REINFORCE | REINFORCE with baseline |
| Policy network | yes | yes |
| Value network | no | yes |
| Policy weight | `G_t` | `G_t - V_phi(S_t)` |
| Policy loss | `-G_t log pi` | `-Adv_t log pi` |
| Value loss | none | MSE between `V_phi(S_t)` and `G_t` |
| Optimizers | one | two |
| Backward calls per episode | one | two |
| Parameter updates per episode | one policy update | one policy + one value update |
| Expected policy-gradient bias from baseline | not applicable | none when baseline is action-independent and detached |
| Typical gradient variance | higher | lower when value estimates are useful |

## 13. `code-5-old.py` versus the new `code-5-reinforce-policy-gradient-value-baseline.py`

The old code uses a fixed constant:

```python
loss += -(G - 5.0) * log_prob
```

The constant `5.0` is action-independent, so it can serve as a valid baseline,
but it cannot adapt to:

- different states;
- changes in the policy during training;
- differences between early and late episode states.

The new code replaces it with:

```python
advantages = returns - value_estimates
```

This learned baseline is state-dependent and adapts while the policy improves.

## 14. Is `code-5-reinforce-policy-gradient-value-baseline.py` actor–critic?

It has an actor-like policy network and a critic-like value network. However,
the most precise name for this implementation is:

> Monte Carlo REINFORCE with a learned state-value baseline.

The value target is the complete sampled return `G_t`, which is available only
after the episode ends. A typical one-step actor–critic method instead uses a
bootstrapped target or temporal-difference error:

$$
\delta_t = R_t + \gamma V(S_{t+1}) - V(S_t)
$$

and can update before the full episode finishes. `code-5-reinforce-policy-gradient-value-baseline.py` does not perform
those step-by-step TD updates.

## 15. Understanding the printed losses

### Policy loss

The policy loss is an optimization device, not a direct measurement of task
performance. It can be positive, negative, or fluctuate while the policy
improves. The CartPole episode return is the more meaningful performance
measurement.

### Value loss

The value loss measures prediction error against noisy Monte Carlo returns.
It can rise when the policy visits new states or begins producing longer
episodes. A temporarily larger value loss does not necessarily mean training
has failed.

### Mean advantage

As the value network improves, the mean advantage often moves closer to zero:

```text
mean(G_t - V_phi(S_t)) ≈ 0
```

That does not mean the policy stops learning. Individual advantages can still
be positive or negative even when their mean is near zero.

## 16. Why `.mean()` is used

Both scripts average loss terms over the trajectory:

```python
loss = (...).mean()
```

Using a sum is also possible. The mean keeps the gradient scale more comparable
between a short episode and a long episode. It changes the magnitude, but not
the direction, of a single episode's gradient.

## 17. Training and evaluation behavior

During training, actions are sampled:

```python
Categorical(logits=logits).sample()
```

Sampling supplies exploration. During evaluation, both scripts choose:

```python
torch.argmax(logits)
```

This greedy evaluation makes the animation show the action currently preferred
by the trained policy. Evaluation uses `torch.no_grad()` and never calls
`backward()` or `optimizer.step()`, so it does not change either network.

## 19. Summary equations

### `code-4-reinforce-policy-gradient-step-by-step.py`

$$
G_t = R_t + \gamma G_{t+1}
$$

$$
L_{policy}
= -\frac{1}{T}\sum_t
G_t\log\pi_\theta(A_t|S_t)
$$

### `code-5-reinforce-policy-gradient-value-baseline.py`

$$
Adv_t = G_t - V_\phi(S_t)
$$

$$
L_{policy}
= -\frac{1}{T}\sum_t
\operatorname{stopgrad}(Adv_t)
\log\pi_\theta(A_t|S_t)
$$

$$
L_{value}
= \frac{1}{T}\sum_t
\left(V_\phi(S_t)-G_t\right)^2
$$

In one sentence:

> `code-4-reinforce-policy-gradient-step-by-step.py` reinforces actions according to their sampled future return,
> while `code-5-reinforce-policy-gradient-value-baseline.py` reinforces actions according to how much better or worse
> that return was than a learned state-dependent expectation.
